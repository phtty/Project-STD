## §1 问题（历史）与现行

STM32F407：SRAM 128KB + CCM 64KB = **192KB**。

### 1.1 曾出现的故障形态（Phase A 堆在 CCM）

| 域 | Used | 上限 | 状态 |
|----|------|------|------|
| SRAM | ~95464B | 128KB | 健康 |
| CCM | 79168B | 64KB | **溢出**（堆 40KB + 1-969 显存） |

根因：**Phase A 把堆放进 CCM**，与大屏显存互斥。不是芯片总容量不足。

### 1.2 现行（堆回 SRAM 36KB + 瘦身后）

| 域 | Used | 上限 | 状态 |
|----|------|------|------|
| SRAM | ≈120820B | 128KB | **健康（~92%）** |
| CCM | 38208B | 64KB | **健康（~58%，仅显存）** |

口径：EIDE 常编 **1-577 3×3**（CCM 与 1-969 同 38208）。详见 [04](./04_current_memory_occupancy.md)。

### 易混数字

| 说法 | 正确含义 |
|------|----------|
| 溢出 ~13KB | **历史** CCM（堆+显存）相对 64KB |
| 堆回 SRAM 缺口 | 当时 ≈5.4KB；以 RTT 等腾挪后已消除 |
| 现行 SRAM ~92% | **链接态**；仍建议实机看堆水位 |

## §3 约束（硬）

1. DMA / ETH / lwIP pbuf 数据 → **只能 SRAM**  
2. CCM 无 DMA → 只适合堆、显存、纯软件缓冲  
3. 改 RAM 前写清 **释放量 / 风险 / 回滚**；改后重采 [04](./04_current_memory_occupancy.md)
