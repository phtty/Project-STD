# 字库芯片更换与移植指导

**状态**: `[指导文档]` `[已验证通过]` `[支持多芯片切换]`

## 1. 背景

本项目支持两种字库芯片配置，可通过 `app_render_chip_select()` 运行时切换:

| 配置枚举 | 芯片型号 | 布局 | 字号 | ASCII 索引 |
|---------|---------|------|------|-----------|
| `FONT_CHIP_W25Q64` | W25Q64 | 非连续(12个独立区块) | 16/24/32 | 原始字符码(不减0x20) |
| `FONT_CHIP_MX25L256` | MX25L25645GM2I-10G | 连续(顺序拼接) | 14/16/20/24/32 | ch[0] - 0x20 |

### 两种布局的核心差异

| 对比项 | W25Q64 (`FONT_CHIP_W25Q64`) | MX25L256 (`FONT_CHIP_MX25L256`) |
|--------|----------------------------|--------------------------------|
| 字号 | 16 / 24 / 32 | 14 / 16 / 20 / 24 / 32 |
| 字库布局 | 非连续, 12个独立区块 | 连续顺序拼接 |
| 地址计算 | 每区块独立 base + X/Y/Z 修正 | 同一公式, Y/Z 补偿块起始偏移 |
| ASCII 索引 | `ch[0]`(原始码) | `ch[0] - 0x20` |
| GBK 索引 | **94列序**: `(高-0xA1)*94 + (低-0xA1)` | **190列序**: `(高-0x81)*190 + ...` |

## 2. 切换 API

### 2.1 头文件声明

```c
/* app_render.h */

typedef enum {
    FONT_CHIP_W25Q64   = 0,  /* W25Q64: 非连续布局, 16/24/32 */
    FONT_CHIP_MX25L256 = 1,  /* MX25L256: 连续布局, 14/16/20/24/32 */
    FONT_CHIP_CNT,
} font_chip_id_t;

bool app_render_chip_select(font_chip_id_t id);
font_chip_id_t app_render_chip_current(void);
```

### 2.2 使用方式

```c
#include "app_render.h"

app_render_chip_select(FONT_CHIP_W25Q64);   /* 切换到 W25Q64 */
app_render_chip_select(FONT_CHIP_MX25L256); /* 切换到 MX25L256 */

font_chip_id_t current = app_render_chip_current(); /* 查询当前 */
```

### 2.3 上电自动选择（DIP2 拨码开关）

上电时 `_render_init()` 自动读取 `DEV_KEY_DIP2` 拨码开关状态选择字库芯片：

| 开关状态 | GPIO 电平 | `get_state()` | 芯片 |
|----------|-----------|---------------|------|
| OFF（位置 0） | HIGH（上拉） | `true` | **W25Q64** |
| ON（位置 1） | LOW（接地） | `false` | **MX25L256** |

**硬件说明**：`DEV_KEY_DIP2` 对应 PE8，内部上拉，active_low。
`_dip_get_state()` 内部执行 `!pl_gpio_read()`，对 GPIO 原始电平取反：
引脚 HIGH（上拉）→ 取反 → `true`；引脚 LOW（接地）→ 取反 → `false`。

选择逻辑封装在 `_dip_font_select()` 中，`_render_init()` 调用它完成上电自动选择。
上电后仍可通过 `app_render_chip_select()` 运行时手动切换。

## 4. W25Q64 地址计算公式（FONT_CHIP_W25Q64）

### 4.1 地址公式

完全复刻01Embedded `func.c` 中6个读取函数的分步计算：

```
FonfAddr  = char_idx * bytes_per_char
sec       = FonfAddr / 4096
page      = (FonfAddr % 4096) / 256
byte      = (FonfAddr % 4096) % 256
readaddr  = (base + sec + X) * 4096 + (page + Y) * 256 + byte + Z
```

**关键**：ASCII 字符索引 `char_idx = ch[0]`（原始码，不减 0x20）。

**GB2312 索引**：`char_idx = (ch[0] - 0xA1) * 94 + (ch[1] - 0xA1)`（94列序，非GBK的190列）。

### 4.2 W25Q64 Flash 参数

- 型号：W25Q64（或兼容 W25Q128）
- 扇区大小：4096 字节
- 页大小：256 字节

### 4.3 字库区块起始扇区

定义在 `01Embedded/USER/FUNC/func.h` 中：

## 5. MX25L256 字库适配（FONT_CHIP_MX25L256）

### 5.1 地址计算

MX25L256 与 W25Q64 共用同一套 sec/page/byte 分步公式：

```
readaddr  = (base + sec + X) * 4096 + (page + Y) * 256 + byte + Z
```

但 MX25L256 的 X=0，Y/Z 用于补偿每个块起始地址的非扇区对齐偏移。
base 为累计字节偏移的扇区号，Y = (偏移 % 4096) / 256，Z = (偏移 % 4096) % 256。

**ASCII 索引**：`char_idx = ch[0] - 0x20`（从空格开始）。
**GBK 索引**：**190列序** — `char_idx = (ch[0] - 0x81) * 190 + (ch[1] >= 0x80 ? ch[1] - 0x41 : ch[1] - 0x40)`。

> **注意**：W25Q64 用 GB2312 94列序，MX25L256 用 GBK 190列序，两者不同！

### 5.2 Flash 参数

- 型号：MX25L25645GM2I-10G
- 总容量：32MB
- 扇区大小：4096 字节

### 5.3 字库布局

按 `STD-main-Orig` 工程的 `g_font_lib[]` 表，每个(字号, 字型, 编码)块在 Flash 中**严格顺序拼接**：

```
[14pt ST ASCII] [14pt FS ASCII] [14pt KT ASCII] [14pt HT ASCII]
[14pt ST GBK]   [14pt FS GBK]   [14pt KT GBK]   [14pt HT GBK]
[16pt ST ASCII] [16pt FS ASCII] [16pt KT ASCII] [16pt HT ASCII]
[16pt ST GBK]   [16pt FS GBK]   [16pt KT GBK]   [16pt HT GBK]
...
[32pt ST GBK]   [32pt FS GBK]   [32pt KT GBK]   [32pt HT GBK]
```

每种字号4种字型的ASCII块连续排列，再连续排列4种字型的GBK块。

### 5.5 base 值推导方法

每个块的 base/Y/Z 由其在 Flash 中的**累计字节偏移**推算：

```
offset = 前面所有块的 unit_size 累加
base   = offset / 4096          （扇区号）
Y      = (offset % 4096) / 256  （页修正）
Z      = (offset % 4096) % 256  （字节修正）
X      = 0                      （无扇区修正）
```

其中每个块的 unit_size：
- ASCII: `sz * ((sz/2 + 7) / 8) * 96`
- GBK:   `sz * ((sz + 7) / 8) * 23940`

## 6. 适配过程中发现并修复的 Bug

### 6.1 GBK 索引公式不统一

**问题**：两种芯片的 GBK 字库使用不同的列序索引：
- W25Q64：**GB2312 94列序** — `(ch[0]-0xA1)*94 + (ch[1]-0xA1)`
- MX25L256：**GBK 190列序** — `(ch[0]-0x81)*190 + (ch[1]>=0x80 ? ch[1]-0x41 : ch[1]-0x40)`

早期代码统一用了 W25Q64 的94列序，切换到 MX25L256 后所有汉字地址错位。

**修复**：通过 `font_chip_config_t.gbk_index_190` 标志区分，`_flash_addr()` 中按配置选择公式。

### 6.2 读取字节数错误

**问题**：`_glyph_bytes()` 返回解包后的像素缓冲区大小（如16x16=256字节），但芯片上每个字模只存打包数据（如16x16=32字节）。读256字节会越界到下一个字模。

```c
// 旧（错误）:
app_font_read_glyph(&key, addr, buf, _glyph_bytes(key));  // 读256字节

// 新（正确）:
dev_storage_read(font, addr, buf, _packed_glyph_bytes(key));  // 读32字节
```

**影响**：虽然显示函数只用前32字节所以看起来"能用"，但读取越界可能导致偶发数据错乱。

### 6.3 自适应字号包含不存在的字号

**问题**：自适应选择器曾尝试14pt和20pt，但 W25Q64 只有16/24/32。现已通过配置化的 `adaptive_sizes` 列表解决——W25Q64 配置只包含 `{FONT_32, FONT_24, FONT_16}`，MX25L256 配置包含全部5种。

### 6.4 ASCII 字符索引错误减去 0x20

**问题**：W25Q64 的01Embedded 使用原始字符码计算字模地址，不减 0x20。

01Embedded `readSixteenAsciiData`:
```c
FonfAddr = ((u32)fontstr) * 16;  // fontstr 是原始字符码，如 'F'=0x46
```

错误实现：
```c
char_idx = ch[0] - 0x20;  // 'F'(0x46) -> 38，但01Embedded 用 0x46=70
```

**影响**：所有 ASCII 字符读取偏移 `0x20 * bpg` 字节，显示完全错误。
- 'F'(0x46) -> 读位置 38 的字模 -> 显示 '&'
- 'W'(0x57) -> 读位置 55 的字模 -> 显示 '7'

现已通过配置化的 `ascii_raw_code` 标志解决。

### 6.5 32pt GB2312 base 值计算错误

**问题**：32pt GB2312 的三个字库区块 base 值与01Embedded `func.h` 中的扇区编号不一致。

| 字体 | 01Embedded 正确值 | 旧代码错误值 | 偏差 |
|------|------------------|-------------|------|
| FS | 1189 | 1188 | -1 扇区 |
| KT | 1465 | 1463 | -2 扇区 |
| HT | 1741 | 1739 | -2 扇区 |

**影响**：32pt 字号下仿宋/楷体/黑体显示中文时，地址偏移 1~2 个扇区（4096~8192 字节）。

### 6.6 MX25L256 base 值全为 0（占位符）

**问题**：切换到 MX25L256 后，`g_font_regions_orig[]` 中所有 base/X/Y/Z 均为 0，导致所有字模地址从 Flash 起始位置读取，完全错乱。

**修复**：从 `STD-main-Orig` 的 `g_font_lib[]` 累加推算每个块的累计字节偏移，再拆分为 sector/page/byte 得到正确的 base/Y/Z 值。

### 6.7 MX25L256 GBK 索引公式错误

**问题**：MX25L256 字库按 GBK 190列序存储汉字，但代码统一用了 W25Q64 的 GB2312 94列序。两种列序的索引差异巨大（如"啊"：94列=0，190列=576），导致汉字地址严重偏移。

**修复**：在 `font_chip_config_t` 中新增 `gbk_index_190` 标志，MX25L256 配置设为 `true`，`_flash_addr()` 中按标志选择 GBK 190列序公式。
