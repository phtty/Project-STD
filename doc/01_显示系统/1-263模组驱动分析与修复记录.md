# 1-263 模组驱动分析与修复记录

**状态**：`[修复完成]` `[编译通过]` `[待实机验证]`

## 1. 适用范围

- 目标文件：`Device/Display/dev_display_1_263.c`
- 模组：1-263（模块码 `1000000263`），P6 户外全彩
- 单张分辨率 32x32；行驱动 16206S（译码器型）；列驱动 2013EP（16 通道恒流）
- HUB75 2 通道/模块（R1G1B1 + R2G2B2），ABC 1/8 扫描

## 2. 模组硬件参数

| 参数 | 值 | 说明 |
|---|---|---|
| 模组代号 | 1000000263 | P6 户外全彩 |
| 单模块像素 | 32x32 | 水平 32 列，垂直 32 行 |
| 行驱动芯片 | 16206S | 译码器型（A/B/C 直通二进制行址，兼容 1-577 时序） |
| 列驱动芯片 | 2013EP | 16 通道恒流，每时钟移入 1 bit/通道，可级联 |
| 扫描方式 | 1/8 扫描 | A/B/C 3-bit 行地址，每扫描线点亮 4 物理行 |
| HUB75 通道数 | 2/模块 | R1G1B1 + R2G2B2 |

## 3. 移位链长度推导（每扫描线每通道 64 bit = 64 时钟）

1/8 扫 → 每扫描线同时点亮 4 物理行；2 通道各管 2 行 →
每通道每扫描线 2 行 × 32 列 = **64 个输出点**。

- 每条数据线（R/G/B × 2 通道）每扫描线需移位 64 bit；
- 2013EP 16 通道 → 每条数据线 **4 颗串联**（4 × 16 = 64）；
- 6 数据线 × 64 时钟 = **384 bit** = 4 行 × 32 列 × RGB，逐位对应，无空位。

与同规格 32x32 1/8 扫模组（1-260，64 时钟/扫描线，点序测试已验证）一致。

## 4. hub75_buff 布局（单模块直排）

```
ch0: line0[64] line1[64] ... line7[64]   (pos 0-511)
ch1: line0[64] line1[64] ... line7[64]   (pos 512-1023)
```

每条 scan line 的 64 字节内部排列：

```
[0..31]   = Y_high, X=0..31
[32..63]  = Y_low,  X=0..31
```

| 通道 | 扫描行 L | Y_low (row_type=1) | Y_high (row_type=0) |
|---|---|---|---|
| ch0 | 0-7 | L | L + 8 |
| ch1 | 0-7 | L + 16 | L + 24 |

`row_dst[y] = ch * 512 + line * 64 + row_type * 32`（row_type: 1=low → +32，0=high → +0）。

## 5. "必须保持 64"根因（旧版 64 宽布局的假象）

旧版照抄 1-577 的 64 宽左右半区布局（PIXEL_ROW=64 → SCAN_LINE_PX=128），
每扫描线发 **128 时钟**。本模组移位链只有 **64 bit**：

1. 前 64 时钟的数据被移出链尾丢弃；
2. 模组实际保留后 64 bit = 64 宽虚拟画布的**右半**（X=32..63）；
3. 右半幅数据落入 [高行 32][低行 32] 链段，行结构完全正确、字形完整 →
   看起来"能显示正常汉字"，实为**只显示右半幅**的假象。

PIXEL_ROW 改 32 时又沿用了 1-577 的左右半区 prepare（半宽 16）：
每行只写入 16+16 列、且低行组偏移错用 16（应为 32）→ 显示残缺，
给人"必须保持 64"的错觉。

| 项 | 修复前 | 修复后 |

| MODULE_PIXEL_COL | 32 | 32 |

| row_dst 低行偏移 | row_type × HALF_W(16) | **row_type × PIXEL_ROW(32)** |
| scan | 128 时钟循环 | **64 时钟循环** |
| set_row | Decoder_set_row | Decoder_set_row（不变，16206S 译码器型） |

## 7. 多模块扩展

若整屏由 2 张 32 列模组级联（64 宽），把 `_1_263_MODULE_ROWS` 改为 2：
SCAN_LINE_PX 自动推导为 128，prepare 的模块循环自动拼接两模块链段，
输出位流与旧版 64 布局完全一致（[左模组高 32][左模组低 32][右模组高 32][右模组低 32]）。

## 8. 待硬件实测确认项

1. **物理屏宽**：整屏是 1 张 32x32 模组还是 2 张级联（64 宽）？本配置按"单张"（MODULE_ROWS=1）实现；若为 2 张需改 MODULE_ROWS=2。
2. **链长示波器确认**：R1 引脚对 CLK 计数，每扫描线应恰好 64 个时钟；若实测 128，说明物理链为 2 段级联（见上条）。
3. **全幅显示确认**：修复后应显示完整 32x32 画面（欢迎文字在 32 宽下由渲染层自适应/截断，属内容层问题，与驱动无关）；若仍只见半幅，检查屏幕实际模组数量。
4. **行组顺序**：若修复后上下 8 行组错位（高/低互换），交换 row_dst 中 row_type 偏移 0/32 的语义即可，当前推导依据旧版 64 布局的显示结果（行序正确）。
