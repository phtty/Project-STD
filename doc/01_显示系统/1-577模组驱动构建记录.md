# 1-577模组驱动构建记录

**状态**：`[已完成]` `[已验证]`

## 1. 适用范围
- 目标文件：`Device/Display/dev_display_1_577.c`
- 目标内容：P5-320x160 户外全彩模组驱动的完整构建过程与参数推导

## 2. 模组硬件参数

| 参数 | 值 | 说明 |
|---|---|---|
| 模组代号 | 1000000577 | P5 户外全彩 |
| 单模块像素 | 64x32 | 水平64列，垂直32行 |
| 物理尺寸 | 320mm x 160mm | 单模块 |
| 行驱动芯片 | RUC7258E | 译码器型（ABC 三线行地址） |
| 列驱动芯片 | ICN2037 | 恒流LED列驱动 |
| 扫描方式 | 1/8 扫描 | ABC 3-bit 行地址 |
| HUB75 通道数 | 2/模块 | R1G1B1 + R2G2B2 |

## 3. 派生参数计算

```
SCREEN_ROWS    = MODULE_ROWS * MODULE_PIXEL_ROW = 1 * 64 = 64
SCREEN_COLS    = MODULE_COLS * MODULE_PIXEL_COL = 1 * 32 = 32
BUFFER_SIZE    = SCREEN_ROWS * SCREEN_COLS = 64 * 32 = 2048
TOTAL_CHANNELS = MODULE_COLS * CHANNELS_PER_MODULE = 1 * 2 = 2
CHANNEL_PIXELS = MODULE_PIXEL_ROW * MODULE_PIXEL_COL * MODULE_ROWS / CHANNELS_PER_MODULE
               = 64 * 32 * 1 / 2 = 1024
SCAN_LINE_PX   = CHANNEL_PIXELS / SCAN_LINES = 1024 / 8 = 128
```

## 4. 缓冲区布局

### 4.1 pixel_map（逻辑帧缓冲）
- 大小：`BUFFER_SIZE = 2048` 字节
- 存储：行优先，`pixel_map[y * screen_rows + x]`
- 坐标系：x 为水平（0-63），y 为垂直（0-31）

### 4.2 hub75_buff（扫描输出缓冲）
- 大小：`BUFFER_SIZE = 2048` 字节
- 布局：按通道和扫描行组织

```
ch0: line0[128] line1[128] ... line7[128]   (pos 0-1023)
ch1: line0[128] line1[128] ... line7[128]   (pos 1024-2047)
```

每条 scan line 的 128 字节内部排列（由 `app_test_led_mapping` 实测确认）：

```
[0..31]   = Y_high, X=0..31
[32..63]  = Y_low,  X=0..31
[64..95]  = Y_high, X=32..63
[96..127] = Y_low,  X=32..63
```

### 4.3 g_bsrr（BSRR 预计算查表）
- 大小：`TOTAL_CHANNELS * 8 * sizeof(_1_577_bsrr_t)` = 2 * 8 * 12 = 192 字节
- 存储位置：CCMRAM（零等待状态，与内核直连）
- 用途：`g_bsrr[ch][color]` 存储通道 ch 在颜色 color（0-7）时的 R/G/B 引脚输出值

## 5. prepare() 像素重排

将 `pixel_map` 的行优先逻辑坐标转换为 `hub75_buff` 的 HUB75 物理移位顺序。

### 坐标变换公式

```c
for (y = 0; y < SCREEN_COLS; y++) {
    ch       = y >> 4;           // 通道号：0 或 1
    local_y  = y & 0x0F;         // 通道内垂直坐标：0-15
    line     = local_y & 0x07;   // 扫描行号：0-7
    row_type = (local_y < 8) ? 1 : 0;  // 1=低行(Y=L), 0=高行(Y=L+8)
    base     = ch * 1024 + line * 128 + row_type * 32;

    // 左半 X=0..31
    hub75_buff[base + 0..31]   = pixel_map[y * 64 + 0..31];
    // 右半 X=32..63
    hub75_buff[base + 64..95]  = pixel_map[y * 64 + 32..63];
}
```

### 行映射关系

| 通道 | 扫描行 L | Y_low (row_type=1) | Y_high (row_type=0) |
|---|---|---|---|
| ch0 | 0-7 | L | L + 8 |
| ch1 | 0-7 | L + 16 | L + 24 |

## 6. scan() 扫描输出

逐像素输出 HUB75 时序，2 通道同时输出：

```c
for (pixel = 0; pixel < 128; pixel++) {
    c0 = hub75_buff[line * 128 + pixel];           // ch0 颜色
    c1 = hub75_buff[1024 + line * 128 + pixel];    // ch1 颜色

    // BSRR 查表输出 6 个 GPIO（ch0 的 R/G/B + ch1 的 R/G/B）
    pl_hub75_bsrr_flush(&bsrr[0][c0].r/g/b);
    pl_hub75_bsrr_flush(&bsrr[1][c1].r/g/b);

    pl_hub75_clock_pulse();  // CLK 上升沿锁存数据
}
```

## 7. set_row() 行驱动

RUC7258E 为**译码器型**行驱动，直接设置 ABC 三线二进制地址即可选通行：

```c
static void _1_577_set_row(uint8_t row) {
    pl_hub75_Decoder_set_row(row);  // HUB75_A/B/C 直接输出二进制
}
```

与 1-260 模组的 SM5266PH（移位寄存器型）不同，RUC7258E 无需 CLK+DATA+LAT 时序。

## 8. 初始化流程

`dev_display_1_577_init()` 由 `hw_dev_initcall` 在 RTOS 启动前自动执行：

1. 绑定 ops 虚表：`prepare` / `scan` / `set_row`
2. 注册显示实例：`dev_display_register()`
3. 预计算 `g_bsrr` 查表（2 通道 x 8 颜色 x {R,G,B} = 48 个 BSRR 值）

## 10. 与 1-260 模组的关键差异

| 对比项 | 1-577 | 1-260 | 1-263（P6） |
|---|---|---|---|
| 行驱动芯片 | RUC7258E（译码器型） | SM5266PH（移位寄存器型） | 16206S（译码器型） |
| 列驱动芯片 | ICN2037 | SM16026S | 2013EP（16 通道） |
| set_row | `Decoder_set_row` | `ShiftRegister_set_row` | `Decoder_set_row` |
| 模块像素 | 64x32 | 32x32 | 32x32 |
| 屏幕像素（1x1） | 64x32 | 32x32 | 32x32 |
| SCAN_LINE_PX | 128 | 64 | 64 |
| CHANNEL_PIXELS | 1024 | 512 | 512 |
| prepare 复杂度 | 左右半拼接（base + base+64） | 线性拷贝 | 整行直排（base，32 列） |

## 11. 后续扩展

当前为 1x1 单模块配置。若需拼接多模块（如 5x5 拼接为 320x160），需修改：

- `MODULE_ROWS` / `MODULE_COLS` 为实际拼接数
- `TOTAL_CHANNELS` 随 MODULE_COLS 增加（每列 2 通道）
- `prepare()` 中的通道/行列映射逻辑
- `scan()` 中的通道遍历范围
