# 1-969显示性能优化与扫描重构说明

**状态**：`[历史过程保留]` `[已完成部分验证]` `[待按当前代码复核]`

## 1. 适用范围
- 目标文件：`Device/Display/dev_display_1_969.c`
- 关联层级：`Device/Display/`、`Platform/`、`Kernel/`
- 相关背景：`-O0` 下 `prepare()` / `scan()` 热路径过重导致闪烁

## 2. 问题背景
1-969 模组在低优化等级下，显示链路中 `prepare()` 与 `scan()` 的执行开销过高，刷新节拍抖动明显，亮度 PWM 与扫描窗口耦合，表现为肉眼可见闪烁。

## 3. 历史过程痕迹
### 3.1 早期判断
- 仅调 `TIM3` / `TIM4` 周期无法稳定消除闪烁
- `-O3` 明显优于 `-O0`，说明代码结构存在可优化空间
- 热路径中存在大量运行时计算、重复索引和分支

### 3.2 五版演进记录
| 版本 | 主要改动 | 结果 |
|---|---|---|
| V1 | 修正 `P5_MODULE_ROWS` 编译错误；`prepare()` 从单层 linear 改为双层 row/col 遍历 | 正常 |
| V2 | `prepare()` 内层改指针步进，消除 `col * 2U` | 正常 |
| V3 | `scan()` 缓存局部参数，改指针步进 | 正常，闪烁减轻 |
| V4 | `prepare()` 表驱动：新增 `row_base[96]` + `row_offset[96]`；`scan()` 6 通道手动展开 | 正常，闪烁明显减轻 |
| V5 | 合并双表为 `row_dst[96]`；补充坐标约定注释 | 正常，闪烁继续减轻 |

## 4. 当前仍然有效的结论
- `scan()` 必须尽量做到只读缓存、只写 GPIO
- `prepare()` 应承担所有复杂映射与重排
- 所有可预计算内容都应表驱动化
- 对外显示语义不能改变，允许内部缓存布局重构
