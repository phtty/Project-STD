# 显示自适应字体黑屏修复记录

**状态**：`[已完成]` `[已验证]` `[历史问题已合并]`

## 1. 适用范围
- 目标文件：`Application/Src/LDI/app_ldi_device.c`
- 目标函数：`display_show`
- 关联设备：E6 显示屏

## 2. 问题背景
E6 在使用自适应字体大小（`font_size=0x00`）显示时会黑屏；后续又发现固定字体模式下 `font_line` 不生效。这两类问题本质上都属于显示参数到渲染位置映射不完整。

## 3. 历史问题
### 3.1 历史问题 A：自适应字体黑屏
当 `font_size=FONT_SELF_ADAPT` 且 `font_line=0` 时，代码未将自适应字体转换为有效字号，渲染器收到无效参数，导致屏幕清空后无内容绘制。

### 3.2 历史问题 B：固定字体行号不生效
固定字体模式下没有统一处理 `font_line`，导致文字总是从第一行开始显示。

## 4. 修复过程
- 统一自适应逻辑，确保 `font_size` 不会长期停留在无效值
- 补齐 `font_line` 的行号定位逻辑
- 对固定字体与自适应字体采用一致的行位置计算方式
- 引入“文本宽度/屏幕尺寸”约束，避免自适应字号选到无法完整显示的尺寸

## 5. 当前仍然有效的结论
- `font_line` 必须参与渲染位置计算
- 自适应模式必须保证最终字号有效
- 固定字体和自适应字体应共享统一的行定位规则
- 文本宽度与屏幕尺寸必须共同参与字号选择

## 6. 与当前代码对照
### 6.1 当前代码已吸收的部分
- 自适应字体黑屏修复逻辑
- 固定字体行号处理逻辑
- 行高/渲染区域计算方式

### 6.2 仍需保留的历史描述
- `font_size=0` 为什么会导致黑屏
- 为什么固定字体与自适应字体必须统一处理 `font_line`
- 为什么要显式区分全屏自适应与按行自适应
