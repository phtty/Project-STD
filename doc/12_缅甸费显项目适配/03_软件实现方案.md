# 03 软件实现方案（协议模块 / 段驱动 / 亮度 / 语音）

## 1. 总体结构

新增两类代码：

1. **段驱动**（TB62726 静态移位 + 亮度 PWM + 闪烁）：建议 `Device/Display/dev_seg_led.{c,h}`（OCP 风格设备抽象，`dev_seg_led` + ops），由缅甸协议模块与自检逻辑调用；简化实施可直接放 Application 层（`app_md_seg_led.c`），二选一，**推荐 Device 层**（与 dev_display 平级，符合分层）。
2. **协议模块**：`Application/Src/ProtocolParser_MianDian/` + `Application/Inc/ProtocolParser_MianDian/`，前缀 `app_md_`，文件拆分与云南/贵州同构：
   - `app_md_proto.h/.c`：注册五步、probe、处理任务、initcall
   - `app_md_proto_parse.h/.c`：帧校验（XOR）、命令分派
   - `app_md_proto_cmd.h/.c`：10 命令执行（显示/亮度/音量/DO/查询/自检）
   - `app_md_proto_voice.h/.c`：0x70 语音内容解析（地址序列或 GBK 文本，随语音方案）

## 2. 协议接入（doc/08 五步注册 + 规则）

按 `doc/08_协议模块接入规则/01_通用规则与模块骨架.md`：

1. `RB_PROVIDE_WEAK(rb_provide_rs485, 768)` / `RB_PROVIDE_WEAK(rb_provide_rs232, 768)`（与其他协议 weak 合并同槽）。
2. `app_proto_acquire_buf(RB_SLOT_RS485|RS232, ...)` 两次。
3. `app_proto_register(md_probe, rb)` ×2（RS485/RS232 各独立 mask，同云南模式）。
4. `app_proto_bind_channel(mask, CH_ID_RS485)` + `CH_ID_RS232`。
5. `app_proto_set_frame_queue(mask, queue)`；`osThreadNew(md_handle_task, ..., 256×4)`；`sw_app_initcall(md_proto_init)`。

**probe 设计**（PURE 契约，仅 `rb_peek`）：

```
首字节 != 0xFF            → FAKE（快拒）
第二字节 != 0xE0          → FAKE（与 FF+len 帧族（四川治超 SC_OL）区分：其第二字节为长度，
                            0xE0=224 会被其误当长度 → 链式聚合中谁 READY 谁消费，互斥靠量产口径）
avail < 20                → WAIT（定长 20 字节帧，等待凑齐）
avail >= 20 且 buf[19] == XOR(cmd^data[0..15])（校验开启时）→ READY, *total_len=20
校验关闭时：avail >= 19   → READY, *total_len=20（第 20 字节一并取走丢弃）
```

- 帧定长 20 字节 → 无需尾字节校验之外的复杂定界；`MD_PAYLOAD_MAX=20`、`MD_QUEUE_DEPTH=3`（静态 SRAM 队列，同云南规模，`_Static_assert` ≤ RB 768）。
- **帧头冲突登记义务**：新帧头 `FF E0` 登记 `doc/05-01 §3.3`；与四川治超（FF+len 帧族，RS485+RS232）的兼容组合登记 §6；queue 深度登记 §4.1。量产口径（EIDE）缅甸与四川治超互斥（`{` 帧族守卫之外，FF 帧族无编译期守卫 → 靠 excludeList + probe 快拒双保险）。

**XOR 校验决策（建议）**：启用校验（拒掉噪声帧），理由：原机已计算 XOR 说明上位机确实发送该字节；原机未比对是缺陷而非协议设计。风险：若缅甸上位机实现有误（因原设备从不校验、错误从未暴露），启用会导致"原机收得到、新机收不到"。对策：`app_md_proto.h` 编译开关 `MD_FRAME_CHECK_XOR`（默认 1），联调期若失配改 0 并记录。

## 3. 命令映射表（10 命令，语义 1:1 复刻原机）

| 命令 | 参数 | 新实现行为 |
|---|---|---|
| 0x10 | [3..14] 12 位 BCD | `md_seg_set_digits(buf[3..14])`：低 4 位查 `ledcode[]`（0x00=熄灭），写入 12 字节段缓冲；清闪烁标志 |
| 0x20 | 同 0x10 | 同上 + 置闪烁标志（0.5s/0.5s） |
| 0x30 | — | 12 字节段缓冲清零 |
| 0x40 | [3]&0x0F<11 | 亮度档写入 `s_md_bright` + W25Qxx 落盘 |
| 0x50 | [3]&0x0F≤7 | 音量：方案 A→WT588D `0xE0+vol`；方案 B→`dev_rs232_voice_volume(vol)`；落盘 |
| 0x60 | — | `channel_send(ch, "FF E0 00", 3)` **回源通道**（改进：原机固定回 UART1；两通道均支持 TX） |
| 0x65 | — | 自检任务（§8）：12 位循环 0→9→全亮，每档 1s，C1/C2 翻转（档 1 置 1、档 9 清 0）；可被下一有效命令打断（沿云南自检模式，`s_md_selftest_abort`） |
| 0x70 | [3..31] | 语音解析（§6）：数字段（0x01~0x09）→十/百/千/万组合序列；非数字字节→直接语音地址/短语；0xFE 结束；逐条播报（任务化，不阻塞） |
| 0x80 | [3]&0x04 | C1（PD14）= (data&0x04)!=0 |
| 0x90 | [3] | C2（PD15）= data!=0 |
| 0x0A | [3] | C3 = data!=0 |
| 0x60 应答 | — | 3 字节 `FF E0 00`，无 XOR（原机同） |

处理任务：`md_handle_task`（栈 256×4）→ `md_parse_frame`（纯函数）→ `md_execute_cmd` 查表分派。除 0x60 外一律不回。

## 4. 段渲染与 96bit 移位

### 4.1 数据模型

```c
/* 12 字节段缓冲：buf[0]=最先移入（最右位），buf[11]=最后移入（最左位），
   bit7=DP，bit6=g，bit5=b，bit4=c，bit3=d，bit2=e，bit1=f，bit0=a */
static uint8_t s_seg_buf[12];
/* BCD 输入：digits[0]=ResvBuf[3]（最左位）→ buf[11]；digits[11]=ResvBuf[14] → buf[0] */
static const uint8_t ledcode[16] = {0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F,
                                    0x00,0x77,0x7C,0x39,0x5E,0x79};
```

- 沿用原机 `ledcode[]` 语义（16 项，含 A~E 字母位；0x0F→'E' 与原机一致）。
- 渲染无点阵字体参与：12 位 7 段 = 12×8=96bit 帧缓冲**直接映射** TB62726 移位顺序，不需要抽象 digit buffer 之外的中间层。

### 4.2 移位输出（1:1 复刻原机节奏，可提速）

```
EN=1（灭）→ LAT=0
for i in 0..11:                    // 96 bit，MSB first，buf[0] 先
    for b in 7..0:
        DATA = (buf[i]>>b)&1
        CLK=0; 延时≈4.3us; CLK=1; 延时≈2.2us
LAT=1; 延时≈4.3us; LAT=0
EN 按当前亮度 PWM 状态输出
```

- 位带（`BITBAND_PERIPH`）或 `HAL_GPIO_WritePin` 均可；频率低（~131kHz）无性能压力；完整一帧 ≈0.73ms，可放在 RTOS 任务中执行（刷新任务优先于协议任务）。
- 提速上限：TB62726 手册 fCLK ≥15MHz，但**以原节奏起步保证与灯板电气兼容**，提速留作优化（需实物验证）。
- 可选项：SPI 硬件外设（SPI2/3）以 MOSI=DATA、SCK=CLK、软件片选做 LAT——96bit=12 字节 SPI 帧 + LAT 脉冲，CPU 零位翻转。列为可选优化，非首版必需。

## 5. 亮度 PWM（11 档）双方案

### 5.1 方案一：软件 PWM 复刻（**推荐**）

完全复刻 8051 T0_ISR 算法，行为逐毫秒一致：

```c
/* 1ms 时基（TIM2 base 重配 1ms 中断 → EventFlag → seg_task；或独立 FreeRTOS 任务 osDelay(1)）*/
counter==0  → md_seg_refresh()   // 重发 96bit + LAT（刷新率 90.9Hz）
counter < s_md_bright → EN=0（亮）
else                  → EN=1（灭）
counter++；counter≥11 → counter=0
```

- 周期 11ms、占空比 = 档位/11（档 0 全灭、档 10 ≈91%，与原机完全一致）。
- EN 为任意 GPIO（方案 A 的 PD0），无引脚约束。
- 1ms 抖动容限宽（显示刷新+亮度用途），普通优先级任务即可；为移位时序稳定建议 `osPriorityHigh`。
- TIM2 现为 2Hz 空闲基时（全库未使用）——重配为 1ms 中断不影响任何模块；或直接用 FreeRTOS 时基任务 `osDelay(1)`（有 ±1 tick 抖动，对亮度观感可接受，首版可接受、终版用 TIM2）。

### 5.2 方案二：硬件 PWM（可选，方案 B 引脚时）

- TIM2 CH1（PA0）：APB1 84MHz，PSC=84-1 → 1MHz；ARR=10 → 周期 11 个计数（≈90.9kHz）。
- CCR = 档位（0~10）→ 高电平时间 = 档位/11。EN 低有效亮 → 设 `PWM2` 极性（或 CCR=10-档位）使"档位大→EN 低占比大"。
- 优点：零 CPU 开销、无抖动；缺点：需占用专用引脚（PA0/PA15），与原机"最后 1ms 固定灭"的细微差异可忽略（占空比恒 = 档/11，档 10 = 100%？ARR=10、CCR=10 → 100% 高 → 全灭，注意！CCR=10 时占空比 10/11 需 ARR=11 周期 12 计数或 CCR 限制，实现时按"低电平占比 = 档/11"校验边沿对齐即可，文档不展开）。

### 5.3 闪烁

- 沿用原机逻辑：闪烁标志 + 半秒翻转（`half_sec_task` 或 seg 任务内计数）；翻转后下次刷新移入全 0（灭半秒）或真实缓冲（亮半秒）。

## 6. 语音方案对比与推荐

### 6.1 方案 A：位带驱动原 WT588D（**推荐**）

| 项 | 内容 |
|---|---|
| 接线 | 4 GPIO（DATA/SCK/CS 输出 + BUSY 输入），经 74HCT125 升 5V / 分压输入，见 02 文档 |
| 软件 | `dev_wt588d.c` 新设备驱动：`wt588d_send_byte`（LSB first，SCK=0→DATA→延时→SCK=1→延时；**延时从原机 300us 缩至 50us~200us 均可**，WT588D 三线为慢速 SPI，手册典型 SCK 周期在 us 级——首版复刻 300us 保兼容，实测后可提速）；`wt588d_play(addr)`、`wt588d_volume(0xE0+v)`、`wt588d_stop(0xFE)` |
| 0x70 处理 | 沿用原机 ConverVoiceSound 组合逻辑（数字→十/百/千/万序列，0x3C 小数点，0xFE 结束，0xFF 终止）逐条播报，每条等 BUSY 释放；播报循环内喂 IWDG（对应原机播报中喂 WDT） |
| 优点 | **保留原缅甸语音资源**（WT588D 内烧录的缅甸语/短语地址 0x0A 元、0x22 您好、0x24 谢谢、0x2F 免费、0x3D 自检等全部沿用）；不改语音硬件；地址码语义零翻译 |
| 风险 | WT588D 需要随接口板移栽/保留（现场确认语音芯片在主板还是灯板）；三线时序需实测验证 |

### 6.2 方案 B：改接 STD 现有 RS232 TTS 板（USART6）

| 项 | 内容 |
|---|---|
| 接线 | 无 GPIO，直接用 USART6（`CH_ID_RS232_1`，语音 TX 专用）→ RS232 TTS 板 |
| 软件 | 复用 `dev_rs232_voice_play`（`FD 00 len 01 01 + GBK`）与 `dev_rs232_voice_volume`；新增"地址码→GBK 文本"映射：数字 1~9→「一…九」、0x0C~0x0F→「十/百/千/万」、0x0A→「元」、0x22→「您好」、0x24→「谢谢」、0x2F→「免费」、0x3D→「系统自检」等 |
| 优点 | 零接线、复用现成驱动；TTS 板已在 STD 平台量产验证 |
| 风险 | **TTS 板语音语言**：若现场需缅甸语，中文 TTS 板不满足 → 需换缅甸语语音板（型号未知）；短语语义需逐条人工核对（0x3A 等未知地址码含义需现场澄清）；播报节奏（数字连读）由 TTS 引擎决定，与原 WT588D 分段播报节奏不同 |
| 适用 | 现场可接受中文语音、且语音板可更换的场景 |

**推荐方案 A**（保留原语音资源与语义，风险最小）；方案 B 作为无 WT588D 资源时的降级路径。

## 7. 参数持久化（亮度/音量）

- 原机：STC IAP EEPROM 0x200 扇区。STD 对应：**W25Qxx 独立 4KB 扇区**（如 LDI 配置扇区前一个），新增 `dev_storage` 实例：
  ```
  记录 8B：magic(4) + bright(1) + volume(1) + crc32(2 截断或 4B→16B 记录)
  ```
- 上电读取：无效/损坏 → 默认 亮度=4（原机默认）、音量=4（**建议值，待现场确认**；原机空白 EEPROM 0xFF → SetVoiceVolume 钳位 7）。
- 0x40/0x50 命令改写时擦写扇区（读-改-写，同 LDI 配置模式）。
- **不占用 Sector1**（网络配置区，避免与 Bootloader/Recovery 三固件布局耦合）。
- 备选：不落盘、每次上电用默认值（改动最小，但现场断电丢失参数，与原机行为不符）。

## 8. 上电自检与 WDT

- 上电：非 WDT 复位 → 全段亮（12×0xFF，EN 最亮档）**6 秒** → 全灭（复刻原机 `System_Init`）。
- 复位原因判定：`__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST)`（原机 WDT 复位跳过自检的对等实现）。
- 0x65 命令自检：独立任务 `md_selftest_task`（栈 256×4），12 位循环 0→9→全亮，每档 1s，C1/C2 第 1 档置 1、第 9 档清 0；**定时推进（1s 分片 osDelay）**，不依赖光敏；`s_md_selftest_running` 防重入、`s_md_selftest_abort` 由下一有效命令置位（沿云南模式）。
- WDT：IWDG 沿用现有 half_sec_task 500ms 喂狗；**语音连播不阻塞**（任务化逐条播报），确保最长阻塞（自检 1s 分片、移位 0.73ms）远小于 IWDG 超时。

## 9. 光敏处理

- 缅甸构建：**停用 `app_light_sensor` 自动调光**（亮度由 0x40 命令控制）；PA5 ADC 可保留读取用于：
  - 自检兼容开关（复刻原机"变亮才推进自检"——可选，默认关闭、定时推进）；
  - "变暗发 0x65 测试帧"原机行为——**默认不实现**（疑似出厂测试遗留），列为待确认项。

## 10. 帧字节示例

- 亮度 6 档：`FF E0 40 06 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 46`
  （XOR = 0x40^0x06 = 0x46；命令+16 数据共 17 字节参与 XOR）。
- 显示 12 位 0~9、A、b：`FF E0 10 00 01 02 03 04 05 06 07 08 09 0A 0B 00 00 00 00 XOR`
  （[3]=最左位 0，[14]=最右位 b；XOR = 0x10^0x00^0x01^…^0x0B = 0x1D）。
- 查询：发送 `FF E0 60 00×16 XOR`，应答 `FF E0 00`。
- 自检：`FF E0 65 3A 3A 3A 3A 3A 3A 3A 3A 3A 3A 00 00 00 00 00 XOR`（原机测试帧样例，0x3A×10）。

## 11. 构建收录与互斥纪律

- Makefile `SRC_APPLICATION`：新增 `ProtocolParser_MianDian/` 目录（dev 全协议构建，probe 链式共存，`FF E0` 快拒与四川治超 FF+len 区分）。
