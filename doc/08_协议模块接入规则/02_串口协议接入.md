# 02 串口协议接入（RS485 / RS232）

> 通用规则见 `01`。本文只讲串口专项：通道与 RB、波特率、接收路径、同槽共存判别、三种变长定界模式、调试定位。

---

## 1. 通道与 RB

| 物理口 | UART | CH_ID | RB 槽 | RB 容量 | 绑定协议（现行） |
|---|---|---|---|---|---|
| RS485 | USART1 | `CH_ID_RS485` (0) | `RB_SLOT_RS485` | **768** | 青海 / RLS / 四川 ETC / MTC / 治超 / 山东 / 贵州 / 云南 |
| RS232-0 | USART3 | `CH_ID_RS232` (1) | `RB_SLOT_RS232` | **768** | 青海 / 四川 ETC / MTC / 治超 / 山东 / 贵州 / 云南 |
| RS232-1 | USART6 | `CH_ID_RS232_1` (6) | 无 | 无 | **仅语音 TX，禁止任何协议 bind** |

- 尺寸定义：`app_dispatch.h:37-39`（`RB_SIZE_RS485 (768U)`、`RB_SIZE_RS232 (768U)`）。
- 通道 ID 枚举：`app_dispatch.h:47-55`；`CH_ID_RS232_1` 注释明示「[仅语音 TX] USART6 — 禁止任何协议 bind_channel」。
- **RS232_1 禁绑**是架构约束（doc/05-01 §2.5 / §6）：`app_rs232_1_start()` 是纯 TX 桩（返回 `nullptr`，`app_rs232.c:105-116`），语音经 `dev_rs232_voice_play` → `pl_uart_send(PL_UART6)` 旁路 dispatch。新协议 bind 它会拿到不存在的通道。
- RB 提供方式：协议 TU 内 `RB_PROVIDE_WEAK(rb_provide_rs485, RB_SIZE_RS485)` + `RB_PROVIDE_WEAK(rb_provide_rs232, RB_SIZE_RS232)`（范例 `app_qh_proto.c:12-13`、`app_sc_etc_proto.c:24-25`）。同一槽多 TU 提供 → 链接器保留一份（合并且只占一份 RAM）。

## 2. 波特率（DIP1 统一选择，RS232 + RS485 同步）

- **DIP1 = PE7，active_low**：ON = 115200，OFF = 9600（`app_uart_baud.h:12-13`：`APP_UART_BAUD_ON (115200U)` / `APP_UART_BAUD_OFF (9600U)`）。
- 上电应用：`app_uart_baud_init`（`sw_app_initcall`，`app_uart_baud.c:46-56`）读 `dev_key_get_state(DEV_KEY_DIP1)` → `app_uart_baud_apply`，**先于通道任务启动**（此时 DMA RX 未挂，切换安全）。
- 运行态切换：`app_uart_baud_apply(baud)`（`app_uart_baud.c:20-40`）→ `pl_uart_set_baud(h, baud)` 同步重配 USART1 + USART3，任一路失败即中止（避免两路口不一致）。`pl_uart_set_baud`（`Platform/Src/pl_uart.c:109-135`）内部「停 DMA RX → DeInit → 改 BaudRate → Init → 重挂 RX」。
- **先例**：MTC `7B 40` 改波特率命令 → `_sc_mtc_exec_baud` 判定 `0x2580`(9600)/其他(115200) → `app_uart_baud_apply`（`app_sc_mtc_proto_cmd.c:329-332`，分派 :401）。新协议若带波特率命令，照抄此路径。
- **注意**：DIP2（PE8）已被 app_render 字库芯片选择占用，不得改动（`app_uart_baud.c:43` 注释）。新协议自行设波特率必须经 `app_uart_baud_apply`，禁止直接 HAL 改。

## 3. 接收路径（数据流全景）

```
USART RX DMA（乒乓双缓冲 2×640=1280B 静态缓冲，circular HT/TC + IDLE 增量冲刷）
  │   RS485: Device/Inc/dev_rs485.h:10  RS485_BUF_SIZE (640U)×2（s_rs485_buf）
  │   RS232: Device/Inc/dev_rs232.h:10  RS232_BUF_SIZE (640U)×2
  ▼
ISR（pl_uart.c USART1/3_IRQHandler → uart_idle_handle；DMA HT/TC 经
     HAL_UART_RxHalfCpltCallback / RxCpltCallback 覆盖）
  ▼  osMessageQueuePut(rx_queue, {块号,偏移,长度})   ← rx_queue 深度 2
通道任务 rs485_task / rs232_task（栈 256×4）
  ▼  按块号从 rx_buf + block*block_size + offset 拷 len 字节
  │  app_channel_dispatch(&self->me, src, len)
  │      app_rs485.c:101 / app_rs232.c:105
  ▼  按 ch_proto_map 查掩码 → rb_write（同 RB 指针 seen[] 去重只写一次）
  │  app_dispatch.c:376-419
  ▼  osMessageQueuePut(g_ch_queue, &ch)
frame_dispatch_task（栈 256×4，app_dispatch.c:226）
  ▼  持锁跨整轮探测：链式 probe（见 01 §3）
  ▼  READY → rb_read 整帧 → osMessageQueuePut(frame_queue[i])
协议 handle_task
  ▼  xxx_parse_frame → 查表分派 → channel_send(ch, …) 应答
  ▼  ch->ops->send → pl_uart_send（rs485_send/rs232_send，100ms 超时）
```

协议模块**不需要**接触 UART/DMA/ISR；只做 register/bind/probe/handle。通道任务由 `app_boot` 的 `init_task` 统一启动（`app_boot.c:143-148`），新协议不加启动代码。

## 4. 同槽共存判别技巧

RS485/RS232 槽是多协议链式共享的，probe 写法决定能否共存。三个既有范例：

### 4.1 帧头互斥（最干净）
首字节不同即可天然共存：`'{'`（青海/MTC）vs `0x0A`（ETC）vs `0xFF`（RLS/治超）。各自 probe 首字节快拒互不干扰。

### 4.2 第二字节区分（同帧头）
- **RLS `FF FE` vs 治超 `FF len`**：治超长度字段合法区间 [7,255]，但**显式排除 0xFE(254)**（`app_sc_ol_proto.c:118`：`len_byte < SC_OL_FRAME_LEN_MIN || len_byte == 0xFE` 即 FAKE）——不排除的话治超 probe 会把 RLS 帧当超长帧 WAIT 卡死链式探测；RLS probe 则要求第二字节必须 `0xFE`（`app_rls.c:87-89`）。双向快拒成立，共存合法（doc/05-01 §6）。
- **ETC `0A xx` vs MTC `0A 46`**：命令位互斥——ETC 命令集 {00,01,36~39,40,50}，MTC 只认 `0A 46 0A/0A 46 0D`；ETC probe 对 0x46 走 default FAKE，MTC probe 对非 46 走 FAKE（`app_sc_etc_proto.c:262-263`、`app_sc_mtc_proto.c:131-141`）。

### 4.3 同帧头同字节流 → 必须 EIDE 目录排除互斥
- **青海 `'{'` vs 四川 MTC `'{'`**：MTC 的 '}' 定界变长扫描（上限 74B）对「青海帧数据段含 0x7D（GBK 尾字节）且半帧到达」存在截断认领残余风险。青海 probe 先注册（源码收录序 QH 在前）先认领完整帧，但残余风险无法在 probe 层彻底消除 → **量产必须二选一，靠 `.eide/eide.yml` excludeList 排除目录兜底**（doc/05-01 §6）。
- 判定纪律：**新协议帧头与既有协议重叠时，先到 doc/05-01 §6 查兼容矩阵**；矩阵中标注「禁止同 RB」的组合不得同编，标注「链式允许」的按 4.1/4.2 写 probe。

## 5. 三种变长帧定界模式（照抄范例）

### 5.1 `0x0D` 结尾扫描 — 四川 ETC（`app_sc_etc_proto.c:189-263`）

```
0A <显示方式 00/01> <行号 0~6> <数据…> 0D     （显示帧，变长）
0A 36/37/38/39/50 0D                         （灯控/心跳，定长 3）
0A 40 XX YY 0D                               （亮度，定长 5）
```

probe 要点：
- 首字节 `0x0A` 快拒；命令位查表分定长/变长分支。
- 定长分支：字节数够 → peek 尾字节 `0x0D` 校验 → READY。
- 变长分支：从 `scan_from` 起逐字节扫 `0x0D`（静态显示从 3 起；滚屏帧头 6 字节固定，从 6 起扫，避免 rt/st 控制字节恰为 0x0D 时误定界）；扫到即 READY（`*total_len = off + 1`）。
- **扫描上限**：`max_total = SC_ETC_PAYLOAD_MAX (149U)`（0x0D 最迟索引 148 → 帧 ≤149B）；`avail >= max_total` 仍无 0x0D → FAKE 交重同步；否则 WAIT（帧跨 DMA 块）。

### 5.2 `'}'` 结尾扫描 — 四川 MTC（`app_sc_mtc_proto.c:108-168`）

```
{ <命令 '1'~'9'/'A'/40~45> <参数…> }          （变长，无长度字段、无 BCC）
0A 46 0A / 0A 46 0D                          （主机查询/清屏，定长 3）
```

probe 要点：
- 双帧族分流：首字节 `0x0A` → 只认 `46 0A/0D` 两种，其余 FAKE（还给 ETC）；首字节 `'{'` → '}' 扫描族。
- 命令字合法性预筛：`'1'~'9'` 或 `0x40~0x45`（'A'=0x41 已含），否则 FAKE——**probe 不负责的字段合法性交给 parse**（如 0x41 双义 4B/5B 按帧长细分）。
- 从下标 2 起扫 `'}'`，帧长 = '}' 下标 + 1；上限 `SC_MTC_PAYLOAD_MAX (74U)`（设备队列约束，协议文档上限 228 不采用）；达到上限仍无 '}' → FAKE，否则 WAIT。
- 教训：历史上按「无 BCC 20B / 带 BCC 21B」定长双长度认领导致 `{3 1 1234 } 3 }` 跨帧拼凑乱码，宿主推演脚本 `~/EnvTools/CD-DebugTool-cpp/scripts/probe_sim/sc_mtc_frame_sim.py`（`--old` 可复现旧逻辑）。**变长无长度字段的协议，必须扫定界符，不要猜定长**。

### 5.3 长度字段 — 四川治超（`app_sc_ol_proto.c:94-131`）

```
FF <len 07~FF,0xFE 排除> <cmd> <亮度> <数据…> <BCC> FF
```

probe 要点：
- 首字节 `0xFF` 快拒；第二字节即长度字段。
- 长度下界 `SC_OL_FRAME_LEN_MIN`（7）；`0xFE` 显式排除（见 4.2）；上界由 uint8 天然约束。
- `avail >= len` 后 peek 尾字节（`len-1`）必须 `0xFF` → READY（`*total_len = len_byte`）。
- BCC（五字段异或，不含尾 FF）在 **parse** 校验：`_sc_ol_bcc_calc` 计算 `raw[0..len-3]` 异或对比 `raw[len-2]`（`app_sc_ol_proto_parse.c:19-25, 79-81`）。

选择模式：**有长度字段 → 5.3；有明确结束符 → 5.1/5.2；两者皆无 → 回到协议文档找隐含定界（BCC 位置、固定头部等），实在没有必须与上位机协商加定界**。

## 6. 调试定位

| 断点位置 | 文件:行 | 看到什么 |
|---|---|---|
| 通道任务 dispatch 调用行 | `app_rs485.c:73` / `app_rs232.c:83` | `rx_buf`/`rx_len`：DMA 收到的原始字节（帧是否到达、是否拆块） |

| 链式聚合决策 | `app_dispatch.c:328-336` | `any_wait`/`any_fake` 走向：卡住时看是不是「WAIT 停等」还是「跳 1 字节」 |

**RTT 十六进制 dump 建议**：在 probe READY 分支或 handle_task 收帧处加临时 `SEGGER_RTT_printf` 输出帧头 8 字节十六进制（`pl_rtt` 在 `hw_initcall` 就绪，任何上下文可用）；联调时用 J-Link RTT Viewer 对照上位机发送记录。**提交前删除或注释临时 dump**。

**注意**：RS485 是半双工（RE 方向由 `dev_rs485` 注入），用 485 转 USB 工具抓线时确认 A/B 接法与收发使能。
