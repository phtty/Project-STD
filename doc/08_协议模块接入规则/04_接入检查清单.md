# 04 接入检查清单（step-by-step）

> 新协议接入手把手指南。每步标注「改哪些文件 / 验证什么」。完成后对照本清单自检再提交。

---

## Step 0 — 协议事实收集

在动代码之前，先写清（建议直接写进模块头文件注释）：

1. 帧格式全貌：帧头、长度字段（有无/字节序/范围）、命令字、数据段、校验（CRC/BCC/无）、帧尾/定界符。
2. 定界模式归类：定长 / 结束符定界（`0x0D`、`'}'` 类）/ 长度字段（见 `02 §5`）。
3. 传输通道：RS485 / RS232 / UDP / TCP（Server 还是 Client）/ 波特率是否有命令可改。
4. 应答约定：哪些帧「收到即回」、应答帧格式、错误码。
5. 帧头是否与既有协议重叠 → 先查 `doc/05-01 §6` 兼容矩阵，判定共存策略（互斥快拒 / 第二字节区分 / EIDE 排除）。

## Step 2 — probe 实现与宿主推演

1. 按 `01 §3` 写 probe：首字节快拒 → 头部字段预筛 → 长度/定界扫描 → 尾字节/校验 → 仅 READY/SKIP 写 `*total_len`。
2. **宿主仿真推演**（强烈建议）：仿 `~/EnvTools/CD-DebugTool-cpp/scripts/probe_sim/sc_mtc_frame_sim.py` 写一个纯 Python 镜像 probe/parse 的脚本——喂边界用例（半帧、粘包、伪头、超长、乱字节流）验证状态机流转。该脚本是 MTC '}' 定界改造的直接工具（`--old` 可复现旧 bug），先例意义重大。另参考 `~/EnvTools/CD-DebugTool-cpp/scripts/probe_sim/review_probe_sim.py`。
3. 边界用例至少覆盖：
   - 空缓冲（→ FAKE）
   - 首字节错误（→ FAKE）
   - 帧头正确但半帧（→ WAIT）
   - 完整帧（→ READY，total_len 正确）
   - 超长无定界（→ FAKE 重同步）
   - 两帧粘包连续到达（→ READY 两次）

## Step 3 — 注册与队列

1. 五步注册（`01 §2`），队列静态分配 + `_Static_assert(payload ≤ RB 容量)`（`01 §4`）。
2. 任务栈 `256*4`、优先级 `osPriorityNormal`、帧缓冲 `static`。
3. 队列深度定 2~4 并写明理由（一包多帧粘包 → 深；停等应答 → 浅）。

## Step 4 — 构建与内存核算

1. `make -j8` **全量零告警**（`-Wall -Wextra`；`[[maybe_unused]]` 用于临时未用函数）。
2. `arm-none-eabi-size build/Debug/Project_STD.elf` 对比接入前后：
   - 新增静态量 = 队列体（`DEPTH × (8+PAYLOAD)`）+ RB 体（若该槽原来无提供者）+ 状态变量。
   - 新增任务栈 1KB/个（从 ucHeap，不计 .bss）。
   - **口径警告**：`doc/06-04` 是 EIDE Debug 采样账（编 1-577，排除 1-260/1-969/RLS/AH），**勿用 Makefile 构建产物重采样覆盖 06-04 全表**（06-04 §0 明示）。核算增量用 Makefile 产物，登记时标注口径。
3. 增量超预算（SRAM 空闲仅 ~10KB）→ 回到 Step 3 减 payload/深度，或提案换槽。

## Step 7 — 实机联调

1. **断点路径**（`02 §6` 表）：通道任务 dispatch 行 → `app_channel_dispatch` → 自己的 probe → 聚合决策行（`app_dispatch.c:328-336`）→ handle_task parse 行。
2. **RTT 十六进制 dump**：probe READY 分支或 handle_task 收帧处临时 `SEGGER_RTT_printf` 打印帧头 8B hex，与上位机发帧记录逐字节比对；联调完删除。
3. **回执测试帧样例**（发给设备，观察渲染/应答）：

| 协议 | 测试帧（十六进制） | 预期 |
|---|---|---|
| 四川 ETC 全屏 | `0A 00 00 B2 E2 CA D4 0D`（静态显示/行号0全屏/"测试" GBK） | 全屏显示"测试"，回 `0A 00 0D` |
| 四川 MTC 单行 | `{3 1 1234 } 3 }`（10B，'}' 定界变长，`sc_mtc_frame_sim.py` 文档示例） | 单行渲染，'}' 正确定界不乱码 |
| 四川治超 清屏 | `FF 07 94 00 00 6C FF`（len=7 最小帧：cmd=94 清屏、亮度 00、BCC=FF^07^94^00^00=6C；BCC 算法见 `app_sc_ol_proto_parse.c:19-25`） | 清屏，回 16B/行应答或状态回显 |
| IAP 心跳/测试 | `5A5A5A5A 00000000 00000000 00000000 <CRC32(16B)>`（cmd=00 Test，len=0；CRC 覆盖前 16B） | 协议层应答（cmd01 广播回源 IP 全 FF） |

   > 治超/IAP 样例的 BCC/CRC 值请用上位机工具计算确认后使用；帧结构以协议文档为准，本表只做联调起步。
4. **粘包/拆包验证**：上位机连发两帧（无间隔）与单帧拆两半各发一次，确认 probe WAIT/READY 流转正确。
5. **断链/重连验证**（网络协议）：拔网线 → 确认通道 DOWN、状态机复位（LDI 回 UNINIT 先例，`app_ldi.c:418-419`）→ 恢复后协议自愈。
