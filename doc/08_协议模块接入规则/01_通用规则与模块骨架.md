# 01 通用规则与模块骨架

> 任何协议模块（串口或网络）都适用的规则。串口专项见 `02`，网络专项见 `03`，操作步骤见 `04`。

---

## 1. 目录与命名

### 1.1 目录

```
Application/Src/ProtocolParser_XXX/     ← 实现（.c）
Application/Inc/ProtocolParser_XXX/     ← 头文件（.h）
```

现有实例：`ProtocolParser_QingHai/`、`ProtocolParser_SiChuang_ETC/`、`ProtocolParser_SiChuang_MTC/`、`ProtocolParser_SiChuang_Overload/`、`ProtocolParser_ShanDong/`、`ProtocolParser_GuiZhou/`、`ProtocolParser_YunNan/`。
非地区协议的历史目录 `IAP/`、`LDI/`、`RLS/` 沿用原名，新地区协议一律用 `ProtocolParser_XXX` 命名。

### 1.2 文件拆分惯例

| 文件 | 职责 | 现有范例 |
|---|---|---|
| `app_xxx_proto.c` | 注册（五步）、probe、handle_task | `app_qh_proto.c`、`app_sc_etc_proto.c` |
| `app_xxx_proto_parse.c/.h` | 帧 → `xxx_parsed_cmd_t` 的**纯解析**（不碰外设、不发包） | `app_sc_etc_proto_parse.c`（`sc_etc_parse_frame` :50） |
| `app_xxx_proto_cmd.c/.h` | 命令执行（渲染、GPIO、应答发送） | `app_sc_etc_proto_cmd.c` |
| `app_xxx_proto_voice.c`（可选） | 语音命令，经 `dev_rs232_voice` 旁路 USART6 | `app_qh_proto_voice.c`、`app_sc_mtc_proto_voice.c` |

### 1.3 命名

- 模块前缀：`app_xxx_`（如 `app_sc_mtc_`、`app_qh_`）。
- 模块内静态函数：`_` 前缀（如 `_sc_ol_bcc_calc`，`app_sc_ol_proto_parse.c:19`）。
- 模块状态/句柄：`s_xxx_` 静态变量（如 `s_qh_mask`、`s_sc_etc_queue`）。
- 公开入口：`xxx_proto_init` + `xxx_proto_handle_task`；probe 函数 `xxx_probe_frame` 签名必须匹配 `proto_probe_fn_t`。

## 2. 注册流程五步

以 `app_sc_etc_proto.c:135-190`、`app_qh_proto.c:47-78` 为范例（两者同构）。骨架：

```c
/* 第 1 步：编译期提供通道 RB（weak，多协议同槽自动合并为一个静态体） */
RB_PROVIDE_WEAK(rb_provide_rs485, RB_SIZE_RS485);
RB_PROVIDE_WEAK(rb_provide_rs232, RB_SIZE_RS232);

static proto_mask_t s_xxx_mask;          /* 主通道掩码 */
static proto_mask_t s_xxx_mask_rs232;    /* 第二通道掩码（可选） */

void xxx_proto_init(void)
{
    /* 第 2 步：取 RB（判空链，取不到直接放弃注册） */
    ring_buffer_t *rb = app_proto_acquire_buf(RB_SLOT_RS485, RB_SIZE_RS485);
    if (rb == nullptr) return;

    /* 第 3 步：注册 probe + RB，自动分配 2 的幂掩码 */
    s_xxx_mask = app_proto_register(xxx_probe_frame, rb);
    if (s_xxx_mask == 0) return;

    /* 第 4 步：绑定通道（每逻辑通道独立 mask + bind；可多次） */
    app_proto_bind_channel(s_xxx_mask, CH_ID_RS485);

    /* 第 5 步：创建队列与任务；队列句柄回报框架 */
    s_xxx_queue = osMessageQueueNew(X_QUEUE_DEPTH, X_MSG_SIZE, &s_xxx_queue_attr);
    app_proto_set_frame_queue(s_xxx_mask, s_xxx_queue);

    static const osThreadAttr_t s_xxx_task_attr = {
        .name = "xxx_handle_task", .stack_size = 256 * 4, .priority = osPriorityNormal,
    };
    osThreadNew(xxx_proto_handle_task, NULL, &s_xxx_task_attr);
}
sw_app_initcall(xxx_proto_init);
```

要点（全部为代码事实）：

- **`RB_PROVIDE_WEAK`**（`Kernel/Inc/ring_buffer.h:40`）：生成 `__attribute__((weak))` getter + 内部 `static` 缓冲体。多个协议 TU 提供同名槽 → 链接器只保留一个 getter；未编入任何提供者 → 符号为 0 → `acquire` 返回 `nullptr`（该槽不占 RAM）。getter 名必须是裸标识符 `rb_provide_rj45`（对应 `RB_PROVIDE_RJ45` 宏，`app_dispatch.h:42-44`），勿传宏名（`##` 不二次展开）。
- **`app_proto_acquire_buf(id, size)`**（`app_dispatch.h:121`，实现 `app_dispatch.c:141`）：`id` 是 `rb_slot_t`（RB_SLOT_RJ45/RS485/RS232）；`size` 不得超过槽实际容量（`size > rb->size` 返回 nullptr）；首次调用时 `rb_init` 绑定优先级继承互斥锁。
- **`app_proto_register(probe, rb)`**（`app_dispatch.h:118`，实现 :111）：返回 `proto_mask_t`（2 的幂，0 = 32 槽已满）。多逻辑通道必须**各注册一次拿独立 mask**（LDI 先例：TCP_SERVER / TCP_CLIENT / UDP 三 mask，`app_ldi.c:135-157`），禁止单 mask 绑多通道。
- **`app_proto_bind_channel(mask, ch_id)`**（`app_dispatch.h:120`，实现 OR 累积）：多协议可绑同一通道，同一协议可绑多通道。
- **`app_proto_set_frame_queue(mask, queue)`**（`app_dispatch.h:119`）：框架按 mask 查表推帧。同一协议多 mask 可共用同一队列（QH/LDI/SC 均如此）。
- **`sw_app_initcall(xxx_proto_init)`**：注册进 `__sw_initcall` 段。同层按**链接顺序（源码收录序，非字母序）**执行——`SORT()` 对同名 section 退化为 .o 链接顺序。注册顺序 = probe 优先级顺序：**源码收录序靠前的协议 probe 先被调用**（Makefile `SRC_APPLICATION` 与 `.eide/eide.yml` virtualFolder 收录序当前均约定 QH→SD→GZ→MTC，禁止随意调整；`app_dispatch_init` 靠收录序在协议之前 → 调度系统先就绪）。
- **任务栈惯例 `256*4`（1KB）**：所有协议 handle_task 与通道任务统一 256×4、`osPriorityNormal`；帧缓冲用 `static`，不放大栈。

## 3. probe 契约（PURE）

签名（`app_dispatch.h:90`）：

```c
typedef proto_probe_sta_t (*proto_probe_fn_t)(const channel_t *ch,
        const ring_buffer_t *rb, uint32_t *total_len, uint8_t *aux);
```

返回值四种状态（`app_dispatch.h:65-70`）：

| 状态 | 含义 | 框架动作 |
|---|---|---|
| `PROTO_PROBE_READY` | 完整帧就绪 | `rb_read` 整帧 → 推协议队列 → 本轮结束 |
| `PROTO_PROBE_SKIP` | 帧结构合法但不属于本设备 | `rb_skip` 整帧 → 本轮结束（LDI lane/cert 不匹配先例，`app_ldi.c:356-362`） |
| `PROTO_PROBE_WAIT` | 帧头匹配但数据不足 | 继续试下一协议；置 any_wait |
| `PROTO_PROBE_FAKE` | 明确不是本协议 | 继续试下一协议；置 any_fake |

**强制规则**（doc/05-01 §3.2，全部有代码先例）：

1. **只 `rb_peek`，零副作用**：禁止 probe 内 `rb_read`/`rb_skip`/写业务全局。反例教训：LDI 曾在 probe 里写 `g_ldi.rsp_seq`，已移到 `ldi_handle_task` 读帧后（`app_ldi.c:322` 注释）。
2. **`avail==0` 必须返回 FAKE**：无数据不得盲 WAIT，否则阻塞同 RB 链式探测（每个 probe 首行都是这个判断）。
3. **首字节快拒**：首字节不匹配立即 FAKE（IAP `0x5A`、LDI `0xFF`、ETC `0x0A`、治超 `0xFF`、青海/MTC `'{'`）。
4. **仅 READY/SKIP 写 `*total_len`**（可同时写 `*aux`，如 RLS 写命令高字节、IAP 写 cmd、LDI 写 cmd）。WAIT/FAKE 不得碰输出参数。
5. **长度上下界**：长度字段必须双向校验（治超 `len_byte < SC_OL_FRAME_LEN_MIN || len_byte == 0xFE` 即拒，`app_sc_ol_proto.c:118`；IAP `payload_len > 256` 即拒，`app_iap.c:126`）。
6. **尾字节校验**：定界类帧探到结尾字节才 READY（ETC `0x0D`、MTC `'}'`、治超尾 `0xFF`、RLS 尾 `0x0D 0x0C`）。校验和（CRC/BCC）可放 probe（IAP CRC32、LDI CRC16-XMODEM）或放 parse（治超 BCC 在 `sc_ol_parse_frame`，`app_sc_ol_proto_parse.c:79-81`）。

**链式聚合语义**（`app_dispatch.c:272-336`，写 probe 前必须理解）：

```
同 RB 上按注册顺序逐个 probe：
  READY/SKIP → 消费后结束本轮，回 while(avail>0) 继续取下一帧
  WAIT/FAKE  → 继续试下一协议
一轮无一消费：
  any_wait          → break，等更多字节（禁止 skip——帧头已匹配，数据未到）
  全 FAKE           → rb_skip(1)，逐字节重同步
```

推论：probe 的「帧头匹配 + 数据不足」必须 WAIT；「帧头匹配但结构非法」必须 FAKE（不能 WAIT 卡死链）。

## 4. 帧队列

所有协议帧队列**静态分配**（不占 ucHeap），结构如下（范例 `app_qh_proto.c:19-32`）：

```c
#define X_PAYLOAD_MAX  (…)   /* 协议最大帧长（含头尾） */
#define X_MSG_SIZE     (sizeof(frame_msg_t) + X_PAYLOAD_MAX)
#define X_QUEUE_DEPTH  (3U)
_Static_assert(X_PAYLOAD_MAX <= RB_SIZE_RS485, "X frame must fit RS485 RB");
_Static_assert(X_PAYLOAD_MAX <= RB_SIZE_RS232, "X frame must fit RS232 RB");
static StaticQueue_t s_x_queue_cb;
static uint8_t s_x_queue_buf[X_QUEUE_DEPTH * X_MSG_SIZE];
static const osMessageQueueAttr_t s_x_queue_attr = {
    .name = "x_queue", .cb_mem = &s_x_queue_cb, .cb_size = sizeof(s_x_queue_cb),
    .mq_mem = s_x_queue_buf, .mq_size = sizeof(s_x_queue_buf),
};
```

- **`frame_msg_t`**（`app_dispatch.h:89-96`）：`{ channel_t *ch; uint16_t data_len; uint8_t data[]; }`，`sizeof(frame_msg_t)=8`。handle_task 从 `msg->ch` 拿到源通道用于应答。
- **深度惯例 2~4**：IAP 2（停等升级）/ LDI 4（一包多帧粘包）/ 青海 3 / RLS 2 / ETC 3 / MTC 3 / 治超 3。深度决策依据记录在 doc/05-01 §4.1。
- **payload 上限 ≤ RB 容量且 static_assert**：QH（259 ≤ 768）、SC_ETC（149）、SC_MTC（74）、SC_OL（255）均有 `_Static_assert`；RLS（530）只 assert RS485。网络侧 IAP（1044）/LDI（512）≤ RB_SIZE_RJ45（1536），依赖 `RB_SIZE_RJ45` 注释契约（`app_dispatch.h:37`）。**新模块一律补 static_assert**。
- 队列数据体是 SRAM `.bss` 静态量，必须同步 `doc/06-04` 账。

## 5. 执行层

- **handle_task 查表分派**：阻塞 `osMessageQueueGet` → `xxx_parse_frame(msg->data, msg->data_len)` → 按命令查表调执行函数。范例：`iap_handle_task`（`app_iap.c:70-85`，`g_iap_cmd_table[cmd]`）、`rls_handle_task`（cmd_index_table 线性查表）。
- **parse 纯函数化**：`xxx_parse_frame(const uint8_t *raw, uint16_t raw_len)` 只产出 `xxx_parsed_cmd_t`（含 `sta` 错误码），不发包、不渲染。执行副作用全部在 cmd 层。
- **状态存储**：需要跨帧状态时用模块级 `static`（如 LDI 状态机 `g_ldi.state`；ETC 心跳计时 `s_etc_uptime_s`）。probe 不得读写这些状态（PURE）。
- **应答「收到即回」约定**：解析完成立即在 cmd 层 `channel_send(ch, …)` 应答；解析失败也应答错误码。范例：ETC 屏应答 `0A XX 0D`（00 正常/01 超长/02 帧错，`app_sc_etc_proto_cmd.c:41-47`，失败仍应答 :230）；心跳帧识别后丢弃不应答（`0A 50 0D`）。

## 6. 内存纪律

| 项 | 位置 | 规则 |
|---|---|---|
| 协议帧队列 | SRAM `.bss` 静态 | 不占 ucHeap；新增即改 `doc/06-04` |
| RB 体 | SRAM `.bss`（weak 提供者的 static 缓冲） | 一槽一份；不重复提供 |
| 任务栈 | ucHeap（36KB，`FreeRTOSConfig.h`） | 256×4=1KB/个；新增任务即扣 1KB |
| 帧缓冲 | handle_task 内 `static uint8_t msg_buf[X_MSG_SIZE]` | SRAM 静态，不入栈 |
| 互斥锁/信号量 | `osMutexNew`/`osSemaphoreNew` 动态 | 从 ucHeap 支出（LDI `tx_lock` 先例，`app_ldi.c:162-163`） |

任何新增静态 SRAM（队列、状态、缓冲）都必须同步 `doc/06_SRAM内部分数据迁移/04_current_memory_occupancy.md`（**注意该账是 EIDE Debug 采样口径，勿用 Makefile 构建重采**，见 06-04 §0）。

## 8. 反面清单（评审对照）

- probe 内有 `rb_read`/`rb_skip`/全局写 → 违反 PURE。
- `avail==0` 返回 WAIT → 阻塞链式探测。
- WAIT/FAKE 路径写 `*total_len` → 脏数据污染框架。
- payload 上限 > RB 容量且无 static_assert → 队列越界风险。
- bind `CH_ID_RS232_1` → 语音冲突，禁止。
- 单 mask 绑多逻辑通道 → 违反「每逻辑通道独立 mask」。
- 队列用动态 `osMessageQueueNew(..., NULL)` 非静态 → 增加 ucHeap 压力。
- `{` 帧族协议（QH/SD/GZ/SC_MTC/YN）主文件缺 `g_brace_proto_guard` 编译期互斥守卫（`#ifndef STD_ALL_PROTO` 包裹 + `__attribute__((used))`）→ 量产多 `{` 族编入不再链接报错。Makefile 全协议开发构建定义 `-DSTD_ALL_PROTO` 豁免守卫。
