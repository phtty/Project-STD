# 10 贵州费显协议

> 贵州常规费显协议（协议文档 06 贵州常规费显协议，2020-06-17 修订）接入记录。
> 模块：`Application/Src/ProtocolParser_GuiZhou/` + `Application/Inc/ProtocolParser_GuiZhou/`（前缀 `gz_`）。

## 1. 协议事实（13 命令）

帧格式：`'{'`(0x7B) + 命令字(1B) + 参数长度(1B 二进制) + 参数(变长) + `'}'`(0x7D)，**无校验**。帧总长 = len + 4，len 为二进制字节值（非 ASCII）。

| 命令字 | 名称 | 参数约束（最终实现） | 行为 |
|---|---|---|---|
| `'1'`(0x31) | 主机查询 | len==0 | 回「正常」应答 `7B 31 01 00 7D` 至**源通道**（仅一种应答） |
| `'2'`(0x32) | 自检 | len==0 | 黄色全屏填充 + 语音「系统正在加电自检」 |
| `'3'`(0x33) | 单行显示 | len 3~18；color '0'~'2'（红/绿/黄）；row '1'~'5'（→0~4） | FONT16 渲染，先清行再渲染，GBK 直通 |
| `'4'`(0x34) | 全屏可编辑 | len 4~86；color '0'~'2'；x/y 1B | 按 **x/y 参数坐标**渲染（word_wrap=true）；len>71 文本截断 64 |
| `'5'`(0x35) | 清屏 | len==0 | 整屏黑 + commit |
| `'6'`(0x36) | 固定格式 | len 3~90；color '0'~'2'；x1 '0'客/'1'货；`'|'` 分隔 5 字段 | 见 §2 行文；金额 ≥0.5 元同步播报费额语音 |
| `'7'`(0x37) | 礼貌用语语音 | len==1；idx '0'~'3' | 4 条文明用语 → TTS |
| `'8'`(0x38) | 亮度 | len==1；'0'~'5' | 0=恢复光敏任务；1~5=挂起光敏 + 硬件 {3,4,5,7,8} |
| `'9'`(0x39) | 音量 | len==1；'1'~'5' | 语音板音量 {1,3,5,7,9} |
| `'A'`(0x41) | 外设 | len==1；bit0 绿/bit1 红/bit2 黄闪 | **红优先**：红→车道灯红；否则绿→车道灯绿；黄闪独立 |
| `'B'`(0x42) | 费额语音 | len≥1；金额 ASCII 串（整数/小数） | 金额 ≥0.5 元播报「您好请交费X元」；**不显示任何内容** |
| `0x01` | 全屏点亮（二进制命令字） | len==1；01红/02绿/**03黄** | 整屏 `dev_display_fill` + commit |
| `0x02` | 版本号（二进制命令字） | len==1 | 串口回裸 ASCII `PROGRAM_CODE` + 屏幕红字「版本:PROGRAM_CODE」 |

金额/重量运算全部**整数运算**（分/吨分），无浮点：`gz_amount_to_fen`（parse.c）整数部分×100 + 小数前两位（`%.2f` 语义，第三位起截断）。

## 2. '6' 固定格式显示行文（裸机行文对齐）

参数：x0=color、x1=客/货，随后 5 字段 `车型|金额|余额|信息1|信息2`（客车）或 `车型|金额|余额|总重|超重`（货车）。

- **客车**：
  - 行0 `车型:   %u    型`（如「车型:   1    型」）
  - 行1 `金额:%u.%02u 元`
  - 行2 `余额:%u.%02u 元`
  - 行3 = 信息1 原文（GBK 直通；空行或首字节空格 → 该行不显示）
  - 行4 = 信息2 **不显示**（按设备实测行为）
- **货车**：
  - 有超重（≥0.1 吨）：行0 金额 / 行1 余额 / 行2 `总重:%u.%02u 吨` / 行3 `超重:%u.%02u 吨`
  - 无超重：行0 车型 / 行1 金额 / 行2 余额 / 行3 总重
  - 总重或超重 <0.1 吨 → 该行不显示（空行）
- 语音：金额 ≥0.5 元 → 「您好请交费X元」（X 保留两位小数，如 1.20→「1.20元」；.00 只播整数）。

## 3. 已裁决差异表（协议文档 vs 设备实测 vs 最终实现）

| 命令 | 协议文档原文 | 设备实测行为 | 最终实现（裁决） |
|---|---|---|---|
| '1' 主机查询 | 正常/异常两种应答 | 经固定串口回「正常」帧 | 仅回「正常」帧，回**源通道**（不沿袭固定串口） |
| '2' 自检 | 固定汉字信息及数字 1~9 交替显示 | 老化模式 + 自检语音 | 黄色全屏 + 语音「系统正在加电自检」 |
| '3' 单行 | 未写长度边界 | len≤2 或 len≥19 丢弃 | len 3~18 |
| '4' 全屏 | x/y 按坐标渲染 | 校验 x≤168/y≤72 后**恒按 (0,0)** 渲染；len≤3 或 len>87 丢弃；len>71 截断 64 | **按 x/y 坐标渲染**（青海先例，word_wrap=true）；len 4~86；len>71 截断 64 |
| '6' 固定格式 | 全角冒号「车型: X型」、信息2 显示于第 5 行 | 半角冒号行文、信息2 不显示 | **裸机行文对齐**（见 §2） |
| '7' 礼貌用语 '0' | 「您好！欢迎行驶贵州公路」 | 「您好！欢迎行驶贵州高速公路」 | 用实测文本 |
| '9' 音量 | 1~5 档线性 | '1'~'5' → 语音板音量 1/3/5/7/9 | 映射 {1,3,5,7,9} |
| 'A' 外设 | bit0 绿/bit1 红/bit2 黄闪 | 绿优先（先判 bit0） | **红优先**（`if(red)…else if(green)`） |
| 0x01 全屏点亮 | 01红/02绿/03黄 | 03=蓝 | **03=黄**（按协议文档） |
| 0x02 版本号 | 返回版本号字符串 | 串口回「版本:GZ_FX_P5_V13」+ 屏幕红字显示 | 串口回裸 ASCII `PROGRAM_CODE` + 屏幕红字「版本:PROGRAM_CODE」（对齐实测的附加行为） |
| 上电画面 | 上电显示并播报「祝您一路平安」 | — | **不建 default 文件**（裁决） |

## 4. 帧头冲突纪律

- 贵州 ASCII 命令集 `'1'~'9','A','B'` 与青海 probe 命令集**完全重叠**（同 `{` 帧族、len 字段同构）：全协议构建下青海 probe 先注册（源码收录序 `qh_proto_init` 在前）先认领，贵州 probe 仅承接青海 FAKE 的帧。
- **量产 EIDE 目录排除纪律**：贵州与青海/山东/四川MTC 互斥（`.eide/eide.yml` Debug 目标已启用贵州、排除青海/山东/四川MTC；其他量产目标须启用本协议并排除其余 `{` 帧族）。
- **编译期互斥守卫**：贵州主文件携带 `g_brace_proto_guard`（`#ifndef STD_ALL_PROTO` 包裹、`__attribute__((used))`）——EIDE 量产构建多个 `{` 帧族编入即链接报 `multiple definition`，无法绕过；Makefile 全协议开发构建经 `-DSTD_ALL_PROTO` 豁免共存（probe 注册序纪律约束）。
- 0x01/0x02 二进制命令字不属于青海/山东/四川MTC 的 ASCII 命令集，各 probe 首命令字快拒 → 贵州 probe 可无冲突认领。

## 5. 遗留项

- 0x02 屏幕红字显示版本为对齐设备实测行为的**附加行为**（协议文档仅要求返回版本号），沿用 `PROGRAM_CODE`（`app_boot.h`）常量。
- 版本号落库：`PROGRAM_CODE` 同时由主固件启动时写入 Sector1 `app_info.version`（供 IAP 0x03 上报版本号，见 `doc/07` §13）；0x02 命令本身仍直接应答编译期常量，不读 Sector1。
- '6' 固定格式行文未实现协议文档「信息1/信息2 超 12 字符自动左右滚屏」。
