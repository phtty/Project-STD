# Project_STD 命名约定

- **状态**：v1.1（已评审）
- **适用**：STM32 固件工程全部自研代码（见 §0）
- **目的**：让文件名、签名与注释自证「归属 + 语义」，使人工评审和 Doxygen 文档生成都不需要额外问答
- **总原则（贯穿全文）**：**前缀只承载「离开文件上下文后无法获知」的信息；名字必须自证「这是什么」。**

---

## §0 适用范围与豁免

| 纳入约定 | 豁免（保持原样，不检查、不改名） |
|---|---|
| `Kernel/` `Platform/` `Device/` `Application/` `Compiler/` | `Drivers/`（ST HAL / CMSIS） |
| `boards/<板>/` 下的自研文件、`test/`、`docs/` | `Middlewares/`（FreeRTOS / LwIP / SEGGER RTT） |
| | `boards/<板>/Core/`（CubeMX 生成） |
| | 工具链/库要求固定名：`main`、`Reset_Handler`、`*_IRQHandler`、`HAL_*_Callback`、newlib 桩（`_write`/`_sbrk` 等） |

---

## §1 归属判定（唯一总规则）

**符号前缀由「它定义在哪个 `Inc/` 树」决定，与实现文件位置无关。**

| 定义位置 | 前缀 |
|---|---|
| `Application/Inc/`（含板级覆盖的 `boards/*/Application/Inc/`） | `app_` |
| `Device/Inc/`（含板级覆盖） | `dev_` |
| `Platform/Inc/`（含板级覆盖） | `pl_` |
| `Kernel/Inc/` | **无层前缀，但必须有模块前缀**（见 §1.1） |

- 板级覆盖文件按其**所覆盖的层**取前缀（`boards/*/Platform/Src/pl_eth_board.c` → `pl_`）。
- **无例外**。`pcb_t`/`ccb_t` 属 Application 层，一律 `app_pcb_t`/`app_ccb_t`。

### §1.1 Kernel 层的模块前缀

Kernel 无层前缀（它是零依赖工具库），但**每个模块必须有模块前缀**：

| 文件 | 模块前缀 | 现存偏差示例 |
|---|---|---|
| `ring_buffer` | `rb_` | 已合规 |
| `text_cvt` | `cvt_` | `hex2chr`/`chr2hex`/`HexToStr`/`StrToHex`/`GBKToUTF8`… → `cvt_*` |
| `crc_utils` | `crc_` | 基本合规 |
| `bit_utils` | `bit_` | 已合规 |
| `bcc_utils` | `bcc_` | `bcc_calcu` → `bcc_calc` |
| `initcall` | `initcall_` | `sw_board_init` → `initcall_run_sw`（名字里的 "board" 不成立：它只遍历段，不感知板级） |

**Kernel 额外禁令**：禁止驼峰（`GBKToUTF8`）、禁止用数字当词（`hex2chr`）、禁止无前缀导出。

## §2 类型

| # | 规则 |
|---|---|
| 2.1 | `typedef` 一律 `_t` 结尾 |
| 2.2 | 导出类型 = `<层><模块>_<名词>_t`（层前缀按 §1） |
| 2.3 | 仅 `.c` 内部使用的类型可用短前缀，**但不得出现在任何头文件中** |
| 2.4 | 结构体 tag 与 typedef 同名（tag 不带 `_t`）：`struct dev_storage_ops` / `dev_storage_ops_t` |
| 2.5 | **废弃 `_sta_t`**，统一 `_state_t`（消歧见 §9） |
| 2.6 | 禁止驼峰与无前缀导出类型（`SysInfo_t` ✗ → `dev_sys_info_t` ✓） |

---

## §3 函数

| # | 规则 |
|---|---|
| 3.1 | 导出：`<层><模块>_<动词><宾语>()`，例 `app_screen_commit_bitmap()` |
| 3.2 | 文件级 static：`_<模块>_<动词><宾语>()`，例 `_ldi_probe_frame()` |
| 3.3 | 动词一律**全拼小写**，白名单：`init deinit get set is has can register bind send read write erase start stop load save reset probe dispatch commit extract apply build alloc free` |
| 3.4 | 禁止自造动词与自造缩写（`proc` `hdl` `mgr` ✗） |
| 3.5 | 谓词返回 `bool`：`is_` / `has_` / `can_` 前缀 |
| 3.6 | 线程入口按普通函数命名（动词取 `task`）：导出 `app_dispatch_task`，static `_display_scan_task` |
| 3.7 | initcall 包装函数按普通函数命名（`_render_init` / `dev_display_init`），不加 `_initcall` 后缀 |
| 3.8 | 模块生命周期动词（`init`/`deinit`/`start`/`stop`/`load`/`save`/`reset`）可省略宾语，因为模块自身即宾语（`app_ldi_init` ✓）；其余动词**宾语必填** |

## §4 变量与数据

| # | 规则 |
|---|---|
| 4.1 | 文件私有数据：`s_<物>`。**不要求带模块名**（文件即模块上下文）；`<物>` 若在文件内不足以唯一指认，可用**说明性限定词**，但那是描述而非模块前缀 |
| 4.2 | 跨文件数据：`g_<模块>_<物>`。**必须带模块名**（已脱离文件上下文），**不带层前缀** |
| 4.3 | 局部变量不加前缀 |
| 4.4 | `bool` 变量用形容词（`is_initialized`、`exti_key_pressed`），禁止 `b_` 匈牙利前缀 |
| 4.5 | 编译期标量常量用 §6 的宏或 §7 的枚举，不用 `static const` |
| 4.6 | **`g_` 与 `s_` 不得混用**：文件 `static` 一律 `s_`（现存 `g_tcp_server`/`g_udp`/`g_rs485`/`g_w25qxx` 均为误用） |

### §4.7 架构约束（不只是命名）

> **`g_` 变量只允许在其所属模块的 `Inc/` 头中声明；跨模块引用必须改为 API。**

这是 SOLID 的硬要求：全局变量是模块内部跨文件共享的手段，不是跨模块接口。
**现行违规**：`g_config` 声明在 IAP（`Application/Inc/IAP/app_iap_cfg.h:72`），却被 LDI 直接解引用（`Application/Src/LDI/app_ldi.c:108-109`）→ 应改为 IAP 提供 API。

> **例外**：`const` **能力表/虚表**（如 `g_flash_int_ops`）不受此限——它是不可变接口，导出即 API，正是 DIP 的接缝。本约束针对的是**可变状态**。

## §5 自注释规则

**仅对导出符号与结构体成员强制；局部变量从宽。**

| # | 规则 | 反例 → 正例 |
|---|---|---|
| 5.1 | **变量/成员的末词 = 其类型的类别词**（可机械检查） | `ldi_ctx_t g_ldi` → `g_ldi_ctx`；`mqtt_ccb_t g_mqtt` → `g_mqtt_ccb`；`app_flash_iap_sys_info_t *g_config` → `g_iap_sys_info` |
| 5.2 | **禁止裸模块名**（只说模块、不说是什么） | `g_ldi`、`g_mqtt`、`g_dispatch`、`s_ah_mqtt` 一律不合格 |
| 5.3 | **时间量必须带单位** | `timeout` → `timeout_ms`；`period` → `period_us` |
| 5.4 | **无信息词必须带限定**：`data` `info` `buf` `handle` `flag` `cb` `tmp` 单独出现不合格 | `buf` → `rx_buf`；`flag` → `ready_flag` |
| 5.5 | **布尔断言要完整** | `is_valid` → `is_config_valid` |
| 5.6 | **函数指针必须 `_fn` 结尾**；不得用动词短语命名变量 | `g_phy_get_link` ✗ → `s_phy_link_fn` |

**类别名词白名单**（可扩展登记）：
`ctx` `dev` `ccb` `pcb` `queue` `sem` `mutex` `lock` `task` `handle` `attr` `buf` `pool` `table` `list` `cfg` `state` `flag` `mask` `cnt` `idx` `addr` `len` `port` `fn` `ops` `hook` `timer` `timeout` `period` `level` `thresh`

## §6 宏与数值常量

| # | 规则 |
|---|---|
| 6.1 | `<MODULE>_<物>` 全大写；带参宏同样全大写 |
| 6.2 | 数值常量**必须带单位/量纲后缀**，白名单：`_MS _US _S _LEN _BYTES _CNT _MAX _MIN _HZ`；新单位需登记 |
| 6.3 | `BOARD_*` 仅供**板级硬件事实**，只能定义在 `boards/<板>/`；跨板共享常量放模块 |
| 6.4 | 禁止用 `#define` 定义类型别名（用 typedef） |

---

## §7 枚举

| # | 规则 |
|---|---|
| 7.1 | 枚举类型名同 §2（`*_t`） |
| 7.2 | 常量 = **枚举类型名去掉 `_t` 后全大写（含层前缀）+ `_值`**：`app_ccb_state_t` → `APP_CCB_STATE_UP`；`app_pcb_probe_state_t` → `APP_PCB_PROBE_STATE_READY` |
| 7.3 | **禁止裸枚举常量**（C 无枚举作用域） |
| 7.4 | 同一概念只允许一个枚举名与一套常量 |

---

## §8 回调与虚表

| # | 规则 |
|---|---|
| 8.1 | 函数指针 typedef **一律 `*_fn_t`**；废弃 `*_cb_t` 与裸 `*_fn` |
| 8.2 | 虚表类型 `<基类>_ops_t` |
| 8.3 | 虚表实例：作为成员时恒名 `ops`；文件级 static 时 `s_<_物>_ops`；**跨文件（extern const）时 `g_<模块>_ops`** |
| 8.4 | 基类子对象必须是派生结构体的**第一个成员**（`container_of` 前提）；基类内部成员顺序不受约束 |

---

## §9 缩写

### §9.1 准入判据

一个缩写只有同时满足三条才可进入白名单：

1. **行业通用**：是嵌入式/系统编程的固定写法，写进任何 C 库都不需要注释；
2. **本工程内无歧义**：不得同时指向两个概念；
3. **已登记**。

**没有通用缩写的词一律全拼**（全拼词永远允许，不受白名单约束）。

### §9.2 白名单

`cfg` `ctrl` `ctx` `msg` `rx` `tx` `buf` `len` `idx` `cnt` `addr` `hdr` `src` `dst` `state` `tmp` `init` `deinit` `alloc`

### §9.3 废弃写法

| 废弃 | 采用 | 说明 |
|---|---|---|
| `config`（用于符号） | `cfg` | `config` 仅用于文件名 |
| `index` | `idx` | |
| `sta` | `state` / `status` | 见下方消歧表 |
| `num` | `cnt` | |
| `cb` | `fn` | 见 §8.1 |

**`sta` 消歧表**（它在本工程内同时指三个词，必须拆开）：

| 现状 | 实际含义 | 改为 |
|---|---|---|
| `pcb_probe_sta_t`、`cfg_rec_sta_t` | state | `app_pcb_probe_state_t`、`dev_cfg_record_state_t` |
| `app_flash_iap_update_sta_t`、`update_sta` | status | `..._update_status_t`、`update_status` |
| `work_sta`、`run_sta` | status | `work_status`、`run_status` |
| `station_hex` | station | **不改**（另一个词） |

> `status` 是无通用缩写的全拼词，永远允许。`update_sta` 是持久化记录 `SysInfo_t` 的成员，**改名安全**——记录布局与 CRC 不变（CRC 算字节，不算源码）。§13 冻结的是布局与线格式，不是 C 成员名。

## §10 文件与目录

| # | 规则 |
|---|---|
| 10.1 | 源/头文件 `<层前缀><模块>[_后缀].c/.h`；后缀仅限 `_cmd` `_cfg` `_ops` |
| 10.2 | 协议目录 = 协议缩写**大写 2–4 字母**；类别目录用单词首字母大写（`Channel`）。**已登记协议缩写**：`IAP` `LDI` `RLS` `CASC` `AHMQ` |
| 10.3 | **`Inc/` 与 `Src/` 的子目录划分必须一致**（都平铺，或都镜像分子目录）。**层根的公共/契约头**不受子目录镜像约束（见 §14 E1） |
| 10.4 | 新增子目录必须同步两套构建的包含路径：Makefile（固件 + 测试两处）与 `.eide/`（两个目标） |
| 10.5 | 板级覆盖文件**保持被覆盖模块同名**（`pl_eth_board.c`、`app_rs232.c`、`board.h`） |
| 10.6 | 测试文件 `test/test_<模块>.c` |

## §12 Doxygen 契约（最小必需集）

| 位置 | 要求 |
|---|---|
| 文件头 | `@file` + `@brief` |
| 每个导出符号（类型 / 函数 / 宏 / 枚举） | 一行 `@brief` |
| 函数返回值 | 非 `void` 用 `@return` 描述；需逐个枚举取值时用 `@retval` |
| 函数参数 | **每个参数都要有 `@param` 条目**——Doxygen 对"只文档了部分参数"会告警。**方向只标给会被函数写入的参数**：`@param[out]`（纯输出，传入值无意义）或 `@param[in,out]`（读改）；纯输入参数（含所有 `const T*`、按值参数，以及只读但不加 `const` 的句柄）用**裸 `@param`**，不标方向 |
| 结构体成员 / 宏 / 枚举常量 | 行尾 `/**< ... */` |
| 按需 | `@note` `@warning` `@see` |

- `@brief` 单行 ≤ 80 列；更长的解释空一行后另起。
- **`@param` / `@return` 放在头文件的声明处**（公开接口即契约所在）。`.c` 定义处的文档块保留散文、**去掉参数标签**——否则 Doxygen 合并"声明 + 定义"时会报 `multiple @param documentation sections` / `too many @param`。
- **一个函数只在一处写参数文档**：头、源两处都写必定重复；只写一部分参数也会报"参数未文档"。
- `@defgroup` / `@ingroup` 本轮不要求。
- 存量注释**不做专门 retrofit**，随改动触达补。

**示例**（`Device/Inc/dev_storage.h`）：

```c
/**
 * @brief 从存储读取数据
 * @param d     存储设备
 * @param addr  起始地址
 * @param[out] buf   接收缓冲；本函数写入 len 字节
 * @param len   读取长度
 * @return 0 成功，负值错误码
 */
int32_t dev_storage_read(dev_storage_t *d, uint32_t addr, uint8_t *buf, uint32_t len);
```

## §13 禁改清单（改名 ≠ 契约改名）

- 持久化记录的 `name[16]` 归属字符串（如 `"casc_id"`）与记录头布局；
- 协议帧字段名、命令码、帧定界符、校验算法常量；
- 链接脚本符号与段名（`.hw_initcall` 等）、`board.mk` / `Makefile` 目标名；
- HAL / LwIP / FreeRTOS / CMSIS 既有符号。

## §14 例外登记表

| 例外 | 内容 | 原因 |
|---|---|---|
| E1 | 层根公共/契约头不参与子目录镜像（如 `Application/Inc/application.h`、`Platform/Inc/platform.h` 这类聚合头） | 它们是跨模块共享的层门面，不属于任一子模块 |
| E2 | `Platform/Inc/lwipopts.h` 保持 LwIP 上游风格 | 第三方配置面 |
| E3 | `main` / `Reset_Handler` / `*_IRQHandler` / `HAL_*_Callback` / newlib 桩 | 工具链与库固定名 |
| E4 | `sys_now` `sys_jiffies`（LwIP 按名调用）、`heth`（CubeMX 句柄） | 库/生成代码固定名。**注意**：`ethernetif_init`/`ethernetif_input`/`ethernet_link_thread`/`gnetif` 只是 ST 样例惯例，**不在豁免内**，按 §1 改为 `pl_eth_*` |
| E5 | **`.c` 文件的内部实现细节**：文件局部宏、内部结构体及其成员、内部类型、static 符号 | §12 只约束**导出符号**；这些不是接口，逐条写 `@brief` 是低价值机械注释 |
| E6 | **PHY 寄存器位定义**（`DP83848_*` 宏） | 硬件事实，权威来源是 PHY 数据手册；Doxyfile 用 `EXCLUDE_SYMBOLS` 排除 |
| E7 | **`test/`（host 测试）** | 非固件交付物；Doxyfile 用 `EXCLUDE` 排除 |

## §15 本约定不覆盖

- 结构体**内部成员顺序**（除 §8.4 的首成员要求）；
- 注释正文的措辞与长度（除 §12 的标签要求）；
- 第三方与生成代码；
- 编码与换行符（另见文档重构工作项）。

## §16 改名执行与验证协议

**分批执行，每批一个 commit。**

| 批次 | 内容 | 验证 |
|---|---|---|
| B1 符号级（零结构风险） | `base` 统一 + 转型统一 `container_of`；`_sta_t` 消歧；`frame_msg_t`/`dispatch_ctx_t`/`dispatch_rx_listener_t`/`frame_dispatch_task` → `app_dispatch_*`；`pcb_`/`ccb_` → `app_pcb_*`/`app_ccb_*`；静态 `_` 补齐；`_cb_t`→`_fn_t`；`s_`/`g_` 归位与自注释改名 | `make test` |
| B2 前缀级 | 导出类型/函数补层前缀；`dev_cfg_record_*`；裸枚举常量加前缀；颜色枚举归一；Kernel 模块前缀（`cvt_*` 等） | `make test` |
| B3 文件/目录级 | 协议目录改名；`Inc/Src` 镜像；头保护；文件改名 | **Makefile + `.eide` 双构建各编一次**（两个 board 目标） |

**每批完成条件**：

1. `grep -rn '<旧名>'` 在自研层**清零**（`docs/` 与注释除外）；
2. `make test` 15 个套件全绿；
3. B3 额外：`make -j8` 与 `make BOARD=5006048` 各编一次，EIDE 两个目标各编一次。
