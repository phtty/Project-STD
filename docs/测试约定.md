# 测试约定 —— `test/` host 单测的写法契约

> **定位**：规定 `make test` 那 18 个套件**怎么写**（骨架 / 断言 / 桩 / 越界矩阵 / 登记 / 验证）。
> 与 `docs/命名约定.md`（命名与注释契约）、`docs/架构说明.md`（设计理由）并列，三者互不重复。
> **范围**：`test/*.c` 与 `test/stubs/`；固件侧不受本文约束（Doxyfile 已 `EXCLUDE` `test/`，见 `命名约定.md` 例外表 E7）。
> **完成门槛**：`make test` 与 `make BOARD=5006048 test` **都**全绿、失败/UB 命中为 0（`命名约定.md:305`、`AGENTS.md` §7）。
> **行号说明**：本文引用的 `文件:行号` 是 2026-10 审计时的快照；套件在改，**以符号名/主题为准**，对不上时按名字找。

## 0. 纲领

**跑真的生产代码；桩只负责观察外部依赖；每条断言都要能说出"判错时现场是什么症状"。**

推论：
- 能 TU-include 生产 `.c` 就 TU-include（`static` 内部结构直接可见，命令层、探针、任务都能跑真的）；
- 只有 OS / CRC / Flash / Display 这类硬件依赖才做替身（`test/stubs/`，靠 `-I test/stubs` 优先命中）；
- **不要**为了测试在生产代码里开洞，也**不要**复制一份逻辑来测（复制品只能证明"抄得一样"）。
  唯一的例外是**刻意异写的参照实现**（§4.3、§8 E3）。

**规范的可执行形态**：`test/check_conventions.py`（`make lint`，同时是 `make test` 的依赖）与 `test/mutate.py`（`make mutate`）。
测试由 agent 维护、**不经人工审查**，因此**挂不上闸的规定等于不存在** —— 规则与闸的对应关系、例外登记纪律、红灯处置纪律见 **§9**。

## 1. 骨架（在登记范围内可选，超出的要先登记到 §8）

| 事项 | 约定 | 依据 |
|---|---|---|
| 文件名 | `test/test_<模块>.c` | `命名约定.md:210` |
| 断言宏 | **每个套件自带一份**，没有公共 `test.h`；新套件照抄附录 A | `test_cdstd.c` 等 17 份同源 |
| 通过/失败 | `g_pass` / `g_fail` 计数 | 同上 |
| 汇总行 | `printf("\n通过 %d，失败 %d\n", g_pass, g_fail);` | `test_cdstd.c` 末尾 |
| 退出码 | `return g_fail ? 1 : 0;` | 同上 |
| 用例登记 | `main()` 里**顺序调用** `case_xxx()`，不搞表驱动/注册宏 | `test_cdstd.c` 的 `main()` |
| **fork 隔离型套件** | **允许**表驱动登记 + 子进程内标准汇总（父进程只能靠退出码汇总） | `test_cfg_sched.c`、`test_ldi_0ah.c`、`test_iap_cfg.c`；理由见 `test_cfg_sched.c` 文件头 |
| 挂死保护 | 起线程 / 等信号 / **fork 子进程** / **阻塞等待**的套件都必须 `signal(SIGALRM, …)` + `alarm()`，超时打印并 `_exit(2)` | 范式 `test_dispatch.c`；fork 型也要——父进程 `waitpid` 会无限等 |
| 白盒依赖 | TU-include 的生产 `.c` **不进** `TEST_*_SRCS`，但必须在 Makefile 单挂依赖行 | `Makefile` 测试段注释 |

**不要**再新造第三个断言宏版本。已在用的早期变体（附录 B）冻结不动、不再扩散。

## 2. 用例纪律

1. **名字** `case_<主题>`；定义前必须 `/** @brief ... */`，写**为什么**（判错会怎样），不写"做了什么"。
   （存量套件已在 2026-10 审计中一次性补齐；**不再接受**裸 `/**` 的新用例。）
2. **一条 case 一个主题**。正例与反例可以同 case；**越界矩阵单独成 case**（行多、断言多，混在一起读不出重点）。
3. **断言预算**：单个 case ≲ 20 条。计数口径 = **静态书写行数**；宏展开/循环矩阵按"读得下去"判断，别拿运行时展开数当挡箭牌。超了就该拆。
4. **反例必须断言"零副作用"**，不能只断言状态码：不调 `app_render`、不落盘、不写队列、不消费暂存区（FAKE 除外——它的契约恰恰是"前进 1 字节"）。
5. **诊断信息**：用 `CHECK_MSG` 把实际值打出来（`cmd=%02X status=%02X`）。裸 `CHECK` 只用在"条件即结论"的纯断言上。
6. **断言必须能红**：新增或修改断言后做一次反向验证（临时改期望 → 确认变红 → 改回），或跑闸② `make mutate`（见 §9.1）。恒真断言比没有断言更坏。
   - **成功落点**：`CHECK_MSG(1, "…")` 是**允许的惯用法**（共享比较器里代替裸 `g_pass++`，还能把 `what` 打出来，全仓 6 处同类）。要求：落点之前必须有真实的失败路径（`CHECK_MSG(0, …) + return`），且**落点覆盖的矩阵不得为空** —— 0 次迭代的成功落点就是假绿。
7. **未定/可能变的行为：两种处理，必须显式选一种并写注释说明是哪一种**
   - **现状哨兵**（默认；适用于"实现已定，只是将来可能要改"的行为）：**照现状写断言**，并在 case 注释里写明"这是现状口径 + 触发条件 + 将来若改则期望一并改"。范式：`test_casc_master.c` 的 `yours` 越界组（`:1085-1160`）、`test_rs485_slots.c` 的空段组。好处是行为一旦漂移立刻变红，而不是悄悄放过。
   - **待定口径不留断言**（适用于协议方尚未拍板的行为）：只留 TODO 注释（编号 + 等谁定），**不写断言**，免得把未定行为钉死。范式：CDSTD 的 `data_len != 1` 与颜色 `0x34..0x37`。
   - **禁止**不写注释地钉现状 —— 后人无从判断那条断言是契约还是将就。

## 3. 新增一条协议命令的配方

样板：CDSTD 的 A1 / A3（`test/test_cdstd.c`）。

**Step 1 — 备桩**（记录桩，写法见 §4）
- 发送观察：`app_ccb_send` / `app_ccb_send_to`；
- 出图观察：`app_render`（记录 cfg 全字段）+ `render_reset()`；
- 其它外部状态：`app_screen_rows/cols`（假几何）、落盘/网络/持久化的记录桩。

**Step 2 — 造帧助手**：给该命令写一个 `x1_payload(...)` 小助手（一次填好头部 + 载荷），矩阵用例复用，别在用例里手抄字面量。

**Step 3 — 两条 case**

| case | 钉什么 |
|---|---|
| `case_cmd_<命令>` | 正例：应答码/状态字节 + **送往下一层的 cfg 逐字段**（几何、颜色、字号、字型、编码、长度、`persist`、对齐） |
| `case_cmd_<命令>_bounds` | 越界矩阵：每字段低位/高位/边界 + 长度边界 → 失败状态 **且零副作用** |

**Step 4 — 贯通**：在 `case_task_dispatch` 里加一格（真命令表 + 真处理函数 + 真任务取帧），只钉"贯通到了"，**不重复**逐字段断言。

**Step 5 — 收尾**：走 §7 清单。

## 4. 桩与替身

**4.1 桩的五条约束**

1. **只记录，不判断**：断言全部留在用例里，桩里不写 `assert`。
2. **记录成散字段，不整结构拷贝**：`app_render_cfg_t` 的成员带 `const`，`s_last = *cfg` 在 C 里编不过。
3. **签名同形**：桩的声明靠 include **真头文件**得到，生产侧签名一变就编译失败，而不是静默错配。
4. **每个记录桩配 `*_reset()`**，用例开头复位，避免用例间串味。**计数类状态**（非结构体的 `static int s_xxx_calls`）同样要有复位口径，否则"累计判定"会随用例顺序漂。
5. **联合体字段按 `type` 分支读**：`app_render_cfg_t` 是 tagged union，`type != APP_RENDER_TYPE_TEXT` 时不要读 `font_size/text/len`（那是别的成员）。

**4.2 桩的判定边界**

桩**可以**做"环境语义"的排序/计数（例如把写入按序记下来），但**不得替用例下结论**（不得自己判"这个值不对"）。

**4.3 三类合法替身**（登记见 §8）

| 类别 | 例子 | 要求 |
|---|---|---|
| 参照实现 / oracle | `test/dev_display_ref.h`、`test_crc.c` 的 `reference()` | 命名独立、与被测**刻意异写**、不与被测共享实现代码；它的价值在于"两条独立路径互证" |
| 假对端 / 协议模拟 | `test_casc_master.c` 的假从卡 | 允许内置帧长/位图长度校验（那是"对端的行为"），但不得替用例断言 |
| 无头符号手写原型 | `test_isr_preinit.c` 的 ISR 原型 | 该符号无头文件（真机由向量表引用），只能手写；要在注释里写明来源与不变量 |

## 5. 越界矩阵速查

协议命令的输入都是"码 + 长度 + 坐标"。历史缺陷集中在**只判上界、漏低位**，矩阵按此铺：

| 维度 | 必测取值 | 为什么 |
|---|---|---|
| 协议码 | `<base`（如 0x29）、`base`、`max`、`>max`（0x38） | "先转换再判据"会把低位回绕成大数被上界拦下；**直接判未转换表达式会漏放行**（A1/A3 各踩过一次） |
| 枚举下标 | 低位 → 负下标 | A1 原版 `_table[code - 0x30]` 直接算负下标 = **数组越界读**（ASan 可抓） |
| 长度 | 头部长度 -1、恰好头部、最小合法、多 1 字节 | 少字节 → `data_len - sizeof()` **uint16 下溢**（65529 字节）；下游若也做减法，同样要钉 |
| 坐标 | `0`、界内、`= 界`、`> 界`、界内最后一位 | 界要用 `app_screen_rows()/cols()`，别抄字面量 |
| 大端合成 | 高/低字节各取 `0x00`/`0xFF` 的组合，且取一个**界内**值 | 只测越界值无法区分字节序（换序后仍然越界）；界内值才能证伪 |
| 计数/序号 | `0`、`1`、`max`、`max+1`、溢出夹取 | 槽位、`device_num`、`offset == avail-1/avail` 一类 |

## 6. 板级

- host 默认板由 `BOARD ?= 3833024` 决定，`TEST_INC` 带 `-I boards/$(BOARD)`；按板跑 `make BOARD=5006048 test`，产物按板分开（`build/<板>/test`）。
- **板无关的映射**（协议码 → 档位/颜色）用**假几何**钉住：断言的是"映射结果"，不是"这块板有没有那一档"，因此不查真字库。
- **需要板级事实**的用例（字库档位、IAP 记录有无、画布/级联）用 `#if BOARD_*` 分支，并在 case 注释里写明**哪块板生效**（范式：`test_font_lib.c`、`test_iap_cfg.c`）。

（`Makefile` 测试段有原文警告："只加依赖的话 make 会编它但永远不跑"；`test` 必须留在 `.PHONY` —— 见 `AGENTS.md` §6 坑 9。）

**加完一条命令后**

- [ ] 套件文件头 `@brief` 覆盖清单同步（写法见 `test_cdstd.c` 头部；**存量套件的散文式范围段不追溯**，但不得与 `main()` 矛盾）

## 9. 自检闭环（无人审查的前提）

测试套件由 agent 维护、**不经人工审查**。因此每条规定的价值 = 它背后那道闸的强度；只在文字里"要求"而不挂闸，等于没要求。

### 9.1 三道闸

| 闸 | 命令 | 查什么 | 何时必须跑 |
|---|---|---|---|
| ① 结构规则 | `make lint`（= `python3 test/check_conventions.py`；已是 `make test` 的依赖） | R1~R9：登记完整性 / 宏变体 / 汇总与退出码 / `@brief` / 用例登记 / 断言预算 / 成功落点 / 禁掩盖 / 挂死保护 | **每次改完 `test/` 立即跑**（秒级，不依赖编译产物） |
| ② 断言有效性 | `make mutate`（= `python3 test/mutate.py --suite <套件> --target <生产 .c> --fail-on-alive`） | 往被测生产代码注入缺陷，看新增/改动的断言能否**杀死**它 | 新增或改动断言后、提交前 |
| ③ 行为与板级 | `make test` + `make BOARD=5006048 test` | 双板全绿、失败/UB 命中为 0（③ 会自动先跑 ①） | 每次改动后 |

闸② 的注意事项（"存活 ≠ 有缺口，也可能是等价变异体"，以及"基线守卫 / 逐变异重编 / 异常还原 / 还原后 touch"四条不变量）写在 `test/mutate.py` 的文档头 —— **先读它再用**，别把等价变异体当缺口去"修"。

|---|---|---|

**规矩**：一条规定若既挂不上闸、又不在 §9.6 的待实施清单里，就不许写进本文 —— 否则它只是愿望。

### 9.3 例外登记纪律（防"消音"）

- 违规**只能**通过 §8 例外表豁免：粒度精确到符号（整文件豁免只允许 R2/R3 这类"变体登记"）；每条必须写明理由 + `§8 E<n>` 锚点。
- **禁止**为了让闸变绿而：删规则 / 放宽规则 / 加整文件豁免 / 把断言改成恒真 / 注释掉断言 / `#if 0` 包起来 / 跳过用例 / 删用例。
- 改 `test/check_conventions.py` 的内建例外表、或 `test/mutate.py` 的 `--allow-alive`，**必须**同步本文 §8（两边漂了就是自欺）。

### 9.4 红灯处置纪律

红灯只允许两种归因，且都要写进提交信息：

| 归因 | 判据 | 动作 |
|---|---|---|
| **期望错** | 被测实现符合协议/契约，是断言写错了 | 改断言；并在提交信息里写明"期望错 + 依据（文档页/行、协议原文）" |
| **实现错** | 断言正确，被测实现有缺陷 | **改被测实现**（不是改断言）；附闸② 的变异证据说明这条断言能抓住它 |

- 拿不准是哪种 → 不许猜：按 §2.7 把它标成待定注释 + 在回复里报告，等确认。
- 任何情况下**不许**通过弱化断言来让红灯变绿（见 §9.3）。

### 9.5 agent 标准动作序列（改测试时照做）

1. `python3 test/check_conventions.py` —— 改之前先确认基线噪音为 0（有噪音先搞清楚是不是别人正在改）。
2. 按 §3 配方改测试；新用例带 `@brief`，反例带零副作用断言。

static int g_fail;

#define CHECK(cond)                                                              \
    do {                                                                         \
