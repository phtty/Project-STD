# 车道显示屏以太网通讯协议

**版本：V1.3**
**适用范围：收费站车道 LED 显示屏（以太网接口）与车道控制机 / 上位机之间的通讯**
**传输层：TCP（主）/ UDP（广播发现、IP 报文应答）**

---

## 1. 概述

本协议定义车道显示屏（以下简称"屏"）与车道控制机（以下简称"上位机"）之间的应用层报文格式与交互流程。协议基于以太网，采用固定帧头 + 长度字段 + CRC16 校验的二进制帧，设计上**以单片机（MCU）可实现性为第一约束**：无分片重组、无会话状态机、无多级校验，一条命令一次交互。

主要特性：

- **以太网直连**：TCP 长连接承载业务数据，UDP 仅承载设备发现（查询 IP 及应答）。
- **固定帧头**：`0x55 0xAA`，紧随包序号，便于接收方快速定界与重同步。
- **包序号（SEQ）**：紧接帧头，每帧递增，配合应答回显、超时重传与重复帧丢弃，实现丢包检测与恢复。
- **单字节命令字**：应答命令字为请求命令字的**高低半字节交换**（如 `0x03` ↔ `0x30`），报文紧凑、配对直观。
- **CRC16 校验**：覆盖包序号至数据域的全部字节，与既有车道设备 CRC 算法保持一致（CRC-16/X-25）。
- **必备功能**：修改 IP（保存后重启生效）、查询 IP、设备重启、全屏填充、显示图片、亮度调节。
- **改址安全**：新地址只写配置、不当场切换，由显式重启命令 `0x09` 统一切换，避免"改完即失联"。
- **图片整帧传输**：一幅点阵图一帧发完，屏侧无需拼接、无需会话管理（144×48 单色图仅 864 字节）。

### 1.1 设计约定

| 项目 | 约定 |
| --- | --- |
| 字节序 | 除特别说明外，多字节字段一律 **大端（网络字节序）** |
| CRC16 字节序 | **低字节在前**（小端），与 CRC-16/X-25 计算结果的内存小端表示一致 |
| 命令字 | 1 字节，见 4.2 |
| 字符编码 | 序列号为 8 字节 ASCII；本版本不含文本显示命令 |
| 屏幕能力 | **仅单色（1bpp）点阵，无灰度**；颜色通过 1 字节颜色码指定（低 3 位有效，置位即点亮对应基色） |
| 帧长限制 | DATA ≤ 8192 字节，单帧总长 ≤ 8201 字节（TCP 允许多段传输） |
| 默认端口 | TCP/UDP **10028**（可配置） |
| 屏默认地址 | IP `192.168.1.100`，掩码 `255.255.255.0`，网关 `192.168.1.1`（出厂值） |

## 3. 网络模型

### 3.1 拓扑与角色

```
        ┌──────────────┐    TCP 10028（长连接，业务数据）   ┌──────────────┐
        │    上位机    │ ─────────────────────────────────▶ │  车道显示屏  │
        │   (Client)   │ ◀───────────────────────────────── │   (Server)   │
        └──────────────┘    UDP 10028（广播发现 / IP 查询） └──────────────┘
```

- 屏作为 **TCP 服务端**，监听 10028 端口；上位机作为客户端发起连接。
- 屏同时监听 **UDP 10028**，用于在未知屏 IP 的情况下通过广播查找设备。
- 同一屏**只保持 1 条** TCP 业务连接；屏按**单连接**实现（一条连接在线期间不接受新连接，须等前一条断开后才能重连）。
- 断链后上位机应在 2 s 后重连，重连间隔指数退避，上限 30 s。

### 3.2 TCP 与 UDP 的分工

| 通道 | 承载命令 | 说明 |
| --- | --- | --- |
| TCP | 全部命令 | 可靠传输；显示图片等大数据必须走 TCP |
| UDP 单播 | 设置 IP、全屏填充、亮度、开关屏、重启 | 低时延控制类命令，可选用 |
| UDP 广播 | 查询 IP（`0x03`）及其应答（`0x30`） | 设备发现，**应答固定走广播**；屏不主动发广播 |

> UDP 通道同样使用第 4 章的完整帧格式；因 UDP 自带报文边界，无需处理粘包，但仍需 CRC16 校验。
> `0x05` 显示图片一律走 TCP；其余命令 DATA 超过 1000 字节时也不得走 UDP（UDP 单包上限 1472 字节）。

### 3.3 帧定界与重同步

接收方应在字节流中搜索 `0x55 0xAA` 作为帧起点，其后必须能按 LEN 取到完整一帧且 CRC16 通过。若出现以下情况，丢弃当前缓冲并从**下一字节**重新搜索帧头：

- `LEN` 超过 8192；
- CRC16 校验失败。

> **本机没有「半帧超时丢弃」**：`LEN` 合法但帧未收齐时探针返回「等待」，半帧会一直占在接收缓冲队首，直到后续字节补齐或连接断开。所以上位机不能依赖「发一半不发了会自动恢复」——发包超时要靠断开重连恢复。（500 ms 是上位机**收应答**的要求，见 5.2。）

> 帧头 2 字节 + 紧随的 2 字节 SEQ 使误同步概率极低：一旦在错误位置命中 `55 AA`，CRC 校验几乎必然失败，接收方按上述规则逐字节滑动即可恢复。

## 4. 帧格式

### 4.1 通用帧结构

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | SOF 帧头 | 2 | 固定 `0x55 0xAA` |
| 2 | SEQ 包序号 | 2 | 0x0000–0xFFFF 循环递增，见 4.3 |
| 4 | CMD 命令字 | 1 | 见 4.2 |
| 5 | LEN 数据长度 | 2 | DATA 域字节数，不含 CRC16；0 ≤ LEN ≤ 8192 |
| 7 | DATA 数据域 | LEN | 命令参数，无参数时为 0 |
| 7+LEN | CRC16 校验 | 2 | 覆盖 SEQ、CMD、LEN、DATA（偏移 2 至 6+LEN），低字节在前 |

最小帧长：**9 字节**（LEN=0），最大帧长：**8201 字节**。

### 4.2 命令字规则

命令字为 **1 字节**，高、低两个半字节各有含义：

```
        bit7 bit6 bit5 bit4 │ bit3 bit2 bit1 bit0
        └──── 方向/角色 ────┘ └──── 功能号 ─────┘
```

- **请求（上位机 → 屏）**：高半字节为 `0x0`，低半字节为功能号，即 `0x01`–`0x0F`。
- **应答（屏 → 上位机）**：高、低半字节**互换**，即 `0x10`–`0xF0`。
- 互换两次即还原，因此一对命令天然成对、便于查表。**当前全部分配如下（与第 6 章一致）**：

| 功能 | 请求 | 应答 |
| --- | --- | --- |
| 查询设备信息 | `0x01` | `0x10` |
| 设置 IP | `0x02` | `0x20` |
| 查询 IP | `0x03` | `0x30` |
| 全屏填充 | `0x04` | `0x40` |
| 显示图片 | `0x05` | `0x50` |
| 显示已存图片 | `0x06` | `0x60` |
| 亮度调节 | `0x07` | `0x70` |
| 显示开关 | `0x08` | `0x80` |
| 重启设备 | `0x09` | `0x90` |

> `0x0A`–`0x0E`（应答 `0xA0`–`0xE0`）为保留码；`0x0F` ↔ `0xF0` 仅用于通用错误应答，`0x0F` 不作为请求码分配。

**约束**：

1. `0x00` 保留（互换后仍为 `0x00`，无法区分方向）。
2. **高低半字节相同的对称码**（`0x11`、`0x22` … `0xFF`）禁止作为命令字使用——它们与自身应答冲突。
3. 每个功能号只能分配给一个功能，且其交换码不得与已分配的命令字重复。
4. 屏收到未定义的请求码时回 `0xF0`（通用错误应答），状态码 `0x01`（失败，不重传）。
5. 可用请求码共 14 个（`0x01`–`0x0E`；`0x0F` 保留给通用错误应答）。若后续功能超限，采用"保留码 + DATA 首字节子命令"或升版本扩展，不得挪用已分配码位。

### 4.3 包序号（SEQ）规则

SEQ 是丢包检测与重传的核心字段，规则如下：

1. **发送方**：每条 TCP 连接（或每个 UDP 对端）独立维护一个 16 位计数器，每发送一帧加 1，`0xFFFF` 后回绕到 `0x0000`。
2. **应答帧**：SEQ **原样回显**请求帧的 SEQ，不使用屏自己的计数器。上位机据此把应答与请求配对。
3. **本协议无设备主动发起的报文**：屏只有在收到请求后才应答，因此所有屏 → 上位机的帧，其 SEQ 均为回显的请求序号。上电、复位、改址生效后均**不主动广播**，避免同网段多台设备同时上电造成广播风暴。
4. **重复帧处理**：屏缓存「最近一次成功处理的 **(通道, SEQ, 命令字)**」。三者都相同时：
   - 不重复执行业务动作（幂等）；
   - 但仍**原样回送上次那份应答**（不重新组包），防止应答在链路上丢失导致上位机反复重传。

   SEQ 相同、命令字不同的按新请求处理。
5. **乱序与丢失**：上位机按 SEQ 连续性判断丢包；未在超时时间内收到应答的 SEQ 记入重传队列（见 5.3）。一帧即一幅完整图片，不存在"半张图"的中间状态。
6. **复位影响**：屏复位后判重缓存清零（屏不使用自己的 SEQ 计数器）；上位机重连后从 `0x0000` 重新计数，双方不得依赖复位前的序号状态。

### 4.4 应答帧通用格式

所有应答帧的 DATA 域首字节为 **状态码**，其后为可选的应答数据：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | STATUS 状态码 | 1 | `0x00` 成功，其余见第 9 章 |
| 1 | RDATA 应答数据 | n | 命令相关，可为空 |

> 屏在收到无法解析或 CRC 错误的帧时**不得应答**（避免噪声报文引发应答风暴）；仅在 CRC 正确但命令字/参数非法时回 `0xF0` 或对应应答码加错误状态。

## 5. 校验与可靠性

### 5.1 CRC16 定义

| 参数 | 值 |
| --- | --- |
| 算法名称 | CRC-16/X-25（与既有车道设备 `0x8408` 算法一致） |
| 多项式 | `0x1021`（反向表示 `0x8408`） |
| 初始值 | `0xFFFF` |
| 输入/输出反射 | 是 / 是 |
| 结果异或 | `0xFFFF` |
| 计算范围 | `SEQ` 起至 `DATA` 末字节（不含 `0x55 0xAA` 帧头、不含 CRC 自身） |
| 校验值 | `"123456789"` → `0x906E` |
| 传输顺序 | 低字节在前 |

C 参考实现：

```c
#define CRC_POLYNOM  0x8408
#define CRC_INIVAL   0xFFFF

unsigned short calc_crc16(unsigned short init_crc, const unsigned char *buf, int len)
{
    unsigned int crc = init_crc;
    int i, k;
    for (i = 0; i < len; i++) {
        crc ^= buf[i];
        for (k = 0; k < 8; k++)
            crc = (crc & 0x0001) ? ((crc >> 1) ^ CRC_POLYNOM) : (crc >> 1);
    }
    return (unsigned short)((~crc) & 0xFFFF);
}

/* 组帧：out 需 >= len + 9 字节 */
int build_frame(unsigned char *out, unsigned char cmd, unsigned short seq,
                const unsigned char *data, unsigned short len)
{
    int i = 0, n;
    unsigned short crc;

    out[i++] = 0x55; out[i++] = 0xAA;
    out[i++] = (unsigned char)(seq >> 8);  out[i++] = (unsigned char)(seq & 0xFF);
    out[i++] = cmd;
    out[i++] = (unsigned char)(len >> 8);  out[i++] = (unsigned char)(len & 0xFF);
    for (n = 0; n < len; n++) out[i++] = data[n];

    crc = calc_crc16(CRC_INIVAL, &out[2], i - 2);   /* 从 SEQ 开始 */
    out[i++] = (unsigned char)(crc & 0xFF);         /* 低字节在前 */
    out[i++] = (unsigned char)(crc >> 8);
    return i;
}
```

### 5.2 应答与超时

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| T1 应答超时 | 500 ms | 单帧命令等待应答的时间；显示图片等大帧可放宽至 1 s；`0x09` 用 1 s（应答后还要等复位） |
| N1 最大重传次数 | 3 | 超过后上报通讯故障 |
| T5 重启后恢复时间 | 5 s | 从 `0x90` 到设备重新可用（含网络栈恢复），此后靠上位机查询确认 |

### 5.3 重传规则

1. 上位机发出请求后启动 T1 定时器；收到 SEQ 匹配且状态码为 `0x00` 的应答则停止定时器。
2. T1 超时未收到应答：用**相同 SEQ、相同命令字**重发，最多 N1 次。重发帧内容必须逐字节一致（含 CRC），使屏可以依据 SEQ 判重。
3. N1 次后仍失败：判定链路/设备故障，关闭连接并重连，同时向上层报警。
4. 收到状态码非 `0x00` 的应答：`0x01` 为确定性失败，**不重传**；`0x02` 为可重试失败，按本节规则重发。
5. 一幅图片就是一帧：丢包时整帧重发，屏只需丢弃旧缓冲、整幅重写，无拼接状态。
6. **重启命令例外**：`0x09` 的应答可能因复位过快而丢失。上位机不得因未收到 `0x90` 而反复重发重启命令，应按"设备重启中"处理（见 7.9）。

## 7. 命令详解

### 7.1 查询设备信息 `0x01` / `0x10`

**用途**：上位机读取屏体标识与显示能力，用于计算点阵数据长度、建立设备台账。

应答 DATA（16 字节）：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | STATUS | 1 | 状态码 |
| 1 | 序列号 | 8 | ASCII，全系列**统一填 `chuangdi`**（8 字节，不补 `0x00`）；**不用于区分单台设备**，上位机请按源 IP 区分（见 7.3.3） |
| 9 | 屏宽 | 2 | 像素，如 144 |
| 11 | 屏高 | 2 | 像素，如 48 |
| 13 | 槽位数 | 1 | 本机可用的断电保存槽位数量，**取值 3–16**；上位机据此校验槽位号 |
| 14 | 当前亮度 | 1 | 档位对应的百分比（0/14/28/42/57/71/85/100；关屏为 0），**不是 `0x07` 的写入值** |
| 15 | 屏幕状态 | 1 | bit0 显示输出开、bit1 有已存图片在槽位中 |

> **亮度只有 7 档**：`0x07` 的 0–100 会就近量化到 1–7 档（写 0 实际是 1 档）。所以 `0x01` 报回的百分比与写入值通常不相等（写 50 报 57、写 80 报 85）；关屏时硬件亮度为 0、报 0，与保存的目标值无关。

**点阵数据长度**由屏宽、屏高唯一确定：

```
字节数 = ceil(屏宽 / 8) × 屏高
```

例：144×48 → 18 × 48 = **864 字节**（见 7.5）。

### 7.2 设置 IP `0x02` / `0x20` 【必须】

**用途**：写入屏的 IP 地址、子网掩码、网关与监听端口。**本命令只保存配置，不改变当前运行的网络参数；新配置在屏重启后生效。**

请求 DATA（14 字节）：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | IP 地址 | 4 | 如 `192.168.1.100` |
| 4 | 子网掩码 | 4 | 如 `255.255.255.0` |
| 8 | 默认网关 | 4 | 如 `192.168.1.1` |
| 12 | 端口号 | 2 | 大端，如 10028 = `0x272C` |

应答 DATA：

| 结果 | DATA 内容 | LEN | 整帧长 |
| --- | --- | --- | --- |
| 成功 | `STATUS`(1B) + **回读的 14 字节配置**（从 Flash 实际读回，非简单回显请求） | 15 | 24 |
| 失败 | 仅 `STATUS`(1B) | 1 | 10 |

> 上位机必须**按 LEN 解析**，不能固定读 15 字节。成功应答里的回读值用于确认落盘内容与预期一致，这是「重启前唯一可验证的环节」。

**行为要求**：

1. **参数校验**：IP 首字节为 0、127 或 ≥224（组播/保留/广播），或 `255.255.255.x`；掩码为 `0.0.0.0` 或非连续；端口为 0 —— 以上任一情况回 `0x01`（失败），**不写 Flash、不改运行参数**。网关不校验（`0.0.0.0` = 无网关，合法）。
2. **只写配置不切换**：校验通过后写入非易失存储，回 `0x00` + 回读配置。**当前 IP、当前 TCP 连接、当前显示内容全部保持不变**，屏仍可在旧地址正常通讯。
3. **重启后生效**：新配置在下一次复位（`0x09` 重启命令、断电重启、看门狗复位）时由启动流程加载。
4. **生效确认**：屏上电/复位完成后**不主动广播**。上位机用 `0x03` 查询（见 7.3），应答 `0x30` 中的当前配置即为生效后的新地址；这也避免了同网段多台设备同时上电时的广播风暴。
5. **写入失败**：Flash 写入或校验失败回 `0x01`（失败），原有配置不受影响。
6. 重复设置相同参数应幂等，不产生额外 Flash 擦写（可先比对）。

**推荐操作顺序**（改址必须成对执行，见 8.1）：

```
0x02 设置 IP  →  核对 0x20 应答中的回读配置  →  0x09 重启  →  向新网段广播 0x03 查询，收 0x30 应答  →  用新地址建 TCP
```

> **防失联说明**：因为不当场切换，配置写错时设备仍在旧地址可访问，可重新下发正确参数；只要**不重启**，错误配置永远不会生效。这是把"改 IP"拆成"写配置 + 重启"两步的核心目的。

### 7.3 查询 IP `0x03` / IP 报文 `0x30` 【必须】

**用途**：读取屏当前网络配置、完成设备发现。**应答固定以 UDP 广播发出**，这样同一网段内多台上位机可同时获知设备地址，也避免了上位机源地址不通（多网卡、NAT、跨网段）导致的单播回不去。

#### 7.3.1 请求

请求 DATA：空（LEN=0）。建议以 **UDP 广播**发送至 `255.255.255.255:10028`（或本网段广播地址）。

#### 7.3.2 应答 DATA（15 字节）

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | STATUS | 1 | `0x00` 成功 |
| 1 | IP 地址 | 4 | 屏当前 IP |
| 5 | 子网掩码 | 4 | — |
| 9 | 默认网关 | 4 | — |
| 13 | 端口号 | 2 | 大端 |

> 报文中的地址始终是**当前实际运行的配置**，而不是 `0x02` 刚刚写入、尚未生效的配置。

#### 7.3.3 发送规则

| 触发场景 | 发送方式 | SEQ |
| --- | --- | --- |
| 收到 `0x03` | UDP 广播，`255.255.255.255:10028` | **回显请求 SEQ** |

> 除应答查询外，屏在**任何情况下都不主动发送** UDP 报文（包括上电、复位、改址生效）。设备发现完全由上位机驱动。

**注意**：

1. `0x03` 从 **UDP** 进来时，应答走 UDP 广播（`0x30`）；从 **TCP** 进来时，通道忽略广播标志、沿原 TCP 连接返回。设备发现仍应使用 UDP：广播应答能被同网段所有上位机收到，TCP 只能回给发起方。
2. 本机固定向受限广播 `255.255.255.255:10028` 发送，不计算定向广播地址；上位机若跨网段/多网卡，请把 `0x03` 发到设备所在网段的广播地址，或让网络设备转发广播。
3. 广播帧同样带完整帧头、SEQ 与 CRC16；**全系列设备的序列号相同**（`chuangdi`），因此识别设备请按**源 IP**——按序列号去重会把多台屏合并成一台。

**设备发现流程**：

1. 上位机向广播地址发送 `0x03`，间隔 1 s 重复 3 次（抗 UDP 丢包）。
2. 屏以 `0x30` 广播应答，上位机从**源 IP** 得到设备真实地址，从 DATA 得到配置与端口。
3. 依据**源 IP**建立设备清单，随后建立 TCP 连接进入业务。

### 7.4 全屏填充 `0x04` / `0x40` 【必须】

**用途**：以单一颜色填满整屏（清屏、红灯禁行、绿灯放行、黄灯警示）。整帧仅 10 字节，时延最低。

请求 DATA（1 字节）：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | 颜色码 | 1 | **3 bit 数据**：bit0 = R（红）、bit1 = G（绿）、bit2 = B（蓝），**某位置 1 表示该基色点亮**、置 0 表示熄灭。bit3–bit7 保留，必须填 0 |

颜色码取值与显示颜色（基色叠加，非灰度）：

| 颜色码 | 置位的基色 | 显示颜色 |
| --- | --- | --- |
| `0x00` | 无 | 全黑（熄屏） |
| `0x01` | R | 红 |
| `0x02` | G | 绿 |
| `0x03` | R + G | 黄 |
| `0x04` | B | 蓝 |
| `0x05` | R + B | 品红 |
| `0x06` | G + B | 青 |
| `0x07` | R + G + B | 白 |

应答 DATA：`STATUS`（1B）。

**行为要求**：

- 屏按自身实际安装的基色做位映射：没有对应基色的位被忽略（如双基色 R+G 屏收到 `0x04` 仅蓝 → 全黑；收到 `0x05` R+B → 只亮红）。颜色码只做"亮/灭"，不做灰度调制，亮度统一由 `0x07` 控制。
- 收到合法命令后 **100 ms** 内完成整屏刷新。
- 只改变当前显示内容，**不写入**断电保存区；需要掉电保持请用 `0x05` 的槽位参数。
- **不含亮度参数**：亮度统一由 `0x07` 设置，填充命令不改变亮度。

### 7.5 显示图片 `0x05` / `0x50` 【必须】

**用途**：显示一幅单色点阵图。**整幅图在一帧内传完**，屏侧无分片拼接、无会话状态、无二级校验——收到即整幅写入显示缓冲。

请求 DATA（2 + n 字节）：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | 槽位号 | 1 | `0x00` 仅显示不保存；`0x01`–`0xNN` 同时写入该槽位（断电保存，NN 为设备信息上报的槽位数，3–16） |
| 1 | 颜色码 | 1 | 同 7.4：3 bit 数据，bit0 = R、bit1 = G、bit2 = B，置位即点亮该基色；`0x00` 表示全灭（黑底灭点） |
| 2 | 点阵数据 | n | **必填长度 = ceil(屏宽/8) × 屏高**，不符则回 `0x01` 拒绝；超过本机点阵上限（2800 字节）的帧会被**整帧丢弃且不应答** |

> 屏不做动画/滚动效果：收到即整幅显示，无过渡方式字段。

**点阵数据格式（固定，无像素格式字段）**：

- 1bpp 单色：每字节 8 像素，**bit0 为最左侧像素**，`1` 亮 `0` 灭。
- 按行优先排列：先第 0 行从左到右，再第 1 行……最后一行。
- 每行按字节边界对齐，行尾不足 8 像素补 `0`。

示例（屏宽 144、屏高 48）：

```
行字节数 = 144 / 8 = 18
总字节数 = 18 × 48 = 864
DATA 长度 LEN = 2 + 864 = 866
整帧长度 = 7 + 866 + 2 = 875 字节
```

应答 DATA：`STATUS`（1B）。

**行为要求**：

- **先校验后显示**：检查 LEN 是否等于 `2 + ceil(宽/8)×高`、槽位号是否为 0 或 1..NN（NN = 设备信息上报的槽位数）；不合法直接回错误码，不改动屏幕。
- **双缓冲切换**：点阵先解码/写入后台缓冲，校验通过后整屏切换，避免出现上半屏新图、下半屏旧图。
- 槽位写入（`槽位号 ≠ 0`）时：**先显示、后落盘，落盘完成才应答**（落盘失败回 `0x01`，但显示已生效）。最坏约 2 s，上位机 T1 应 ≥ 2.5 s；落盘期间本协议任务不取新帧，后续命令排队。
- 重复收到同一帧（相同 SEQ）按 4.3 幂等处理。
- 无分片、无 CRC32：整帧 CRC16 已覆盖全部点阵数据；链路错误由 TCP 重传 + CRC16 双重兜底，最坏情况是整帧重发一次（875 字节，可忽略）。

> **本机能力上限**：`0x05` 的点阵上限是 **2800 字节**（`LCSP_BITMAP_MAX_BYTES`，约合 224×100），即 DATA ≤ 2802、整帧 ≤ 2811。协议帧格式允许 LEN ≤ 8192，但**超过本机能力的帧会被整帧丢弃且不应答**（既不回 `0x01` 也不回 `0xF0`）——上位机不得发送超过本机能力的帧。512×64（4096 字节）本机不支持，需分片/扩容。

### 7.6 显示已存图片 `0x06` / `0x60` 【必须】

**用途**：调用屏内断电保存区的图片，无需传点阵，是车道"放行/禁行"切换的最优路径。

请求 DATA（1 字节）：

| 偏移 | 字段 | 长度(B) | 说明 |
| --- | --- | --- | --- |
| 0 | 槽位号 | 1 | `0x01`–`0xNN`（NN 为设备信息上报的槽位数，3–16），该槽位须已保存图片 |

应答 DATA：`STATUS`（1B）。槽位为空或越界回 `0x01`，原显示内容保持不变。

### 7.7 亮度调节 `0x07` / `0x70` 【必须】

**用途**：统一设置屏体亮度；白天/夜间、隧道内外差异较大时必须可调。

请求 DATA（1 字节）：

| 值 | 含义 |
| --- | --- |
| `0x00`–`0x64` | 手动亮度 0–100（0 最暗，100 最亮），**就近量化到 7 档** |
| `0x65`–`0xFE` | 非法，回 `0x01`，不改亮度 |
| `0xFF` | 自动光感（无光感硬件时按 `0x64` 处理） |

> 本机亮度只有 7 档：`level = (percent×7 + 99) / 100`，下限夹到 1。所以写 `0x00` 实际是 1 档（最暗但**不是关屏**，关屏用 `0x08`）；`0x01` 上报的是档位百分比，不是写入值。

应答 DATA：`STATUS`（1B）。

- 亮度值掉电保持；上电恢复上次设置。
- 亮度为全局参数，影响全屏填充、图片、已存图片的所有显示内容。
- 屏可对亮度做非线性校正，但 0 与 100 必须分别为"最暗/最亮"。

### 7.8 显示开关 `0x08` / `0x80`（可选）

请求 DATA（1 字节）：`0x01` 开、`0x00` 关。应答 DATA：`STATUS`（1B）。
关屏仅关闭输出，不影响接收与缓存，重新开屏恢复关闭前的内容；与全屏填充黑（`0x04` + `0x00`）的区别是后者会清掉画面。开关状态**掉电保持**：重启后仍是关屏，需要再发 `0x08 01` 开屏（`0x01` 的 bit0 可查当前状态）。

### 7.9 重启设备 `0x09` / `0x90` 【必须】

**用途**：使屏复位重启，用于**让 `0x02` 保存的 IP 配置生效**，以及远程故障恢复（画面异常、网络栈卡死）。

请求 DATA：空（LEN=0）。
应答 DATA：`STATUS`（1B），`0x00` 表示"已受理，即将重启"。

**行为要求**：

1. **先应答、后复位**：应答发送完成后延迟 **≥ 200 ms** 再复位，保证上位机在链路断开前收到 `0x90`。
2. 复位为整机软复位（等同断电重启）：网络栈重建、Flash 中的 IP 配置被加载、判重缓存清零。显示内容会**按持久化画面重建**（有 `persist=true` 的画面就恢复，没有则显示默认文案），不保证黑屏。
3. 从应答到网络重新可用 ≤ **5 s**；重启后**不主动广播**，由上位机查询确认（见 7.9 上位机操作要求）。
4. 复位前不强制保存画面；如屏支持"上电恢复上次画面"，可在复位前把当前槽位号记入 Flash（可选）。
5. 命令幂等：重复收到**同一条**（相同通道/SEQ/命令字）按 4.3.4 原样重发上次的 `0x90`，**不会触发第二次复位**。**上位机侧必须把「未收到 `0x90`」视为可能的正常现象**（复位过快导致应答丢失或连接被断），按本节的恢复流程处理，不得循环重发。
6. 若 `0x02` 已写入新地址但尚未重启，屏在当前地址仍可正常服务；重启后按新地址运行。

**上位机操作要求**：

- 发送 `0x09` 后等待 `0x90`（超时 1 s）；收到后**主动关闭旧 TCP 连接**，不要等 TCP 超时。
- 随后分两种情况：
  - **改址合重启**：向新网段广播 `0x03` 查询，间隔 1 s 重复，最长 30 s，直到收到 `0x30` 应答，再用新地址建链；
  - **仅故障恢复**（地址未变）：3 s 后重试连接，间隔 2 s / 5 s / 10 s，最多 3 次；也可用 `0x03` 查询代替。
- 30 s 内查询无应答、也无法用原地址建链，判定设备异常，需现场处理。

### 7.10 通用错误应答 `0xF0`

仅当请求的**命令字无法识别**（映射不到 `0x01`–`0x09`）时回 `0xF0`；参数非法（长度/槽位/颜色不对）回**对应命令的应答码 + `STATUS 0x01`**（如 `0x50 01`），不是 `0xF0`。

DATA（2 字节）：`STATUS`(1B) + 原始命令字（1B，回显以便定位）。

`0xF0` 由保留码 `0x0F` 交换而来，仅屏→上位机方向使用。

## 8. 典型交互时序

### 8.1 修改 IP 并确认（写配置 → 重启 → 主动查询确认）

```
上位机                                                          屏
  │  0x02 SEQ=1  {IP/掩码/网关/端口}      ──────────────────▶   │ 校验参数
  │  ◀──────────────────  0x20 SEQ=1 {00, 回读配置}             │ 写 Flash，运行参数不变
  │  （核对回读配置 = 预期值，不符则重新下发 0x02）             │
  │  0x09 SEQ=2  重启                     ──────────────────▶   │
  │  ◀──────────────────  0x90 SEQ=2 {00}                       │ 200ms 后复位
  │  关闭旧连接；向新网段广播 0x03，间隔 1 s 重试（最长 30 s）    │
  │  0x03 SEQ=3（广播）                   ──────────────────▶   │ 启动完成后才应答
  │  ◀────  0x30 SEQ=3 {00, 新配置}  UDP 广播应答               │ 不主动广播
  │  建立新 TCP 连接（新 IP:10028）                             │
```

要点：

- `0x20` 只代表**配置已落盘**，不代表已生效；此时旧地址、旧连接仍然可用。
- 只有查询到的 `0x30` 应答（源 IP 为新地址）才是**生效确认**。屏不会自己冒出来通知，别等广播。
- 查询要容忍设备还没启动完：间隔 1 s 重复，最长 30 s；此间设备不应答是正常的。
- 若 30 s 内查询无应答：设备可能已被改到不可达网段——**重启后它运行在新地址，不会回到出厂地址**，只能现场物理恢复（恢复出厂/按键/DIP，按维护手册）。若还没重启，仍可在旧地址重发 `0x02` 修正。
- 因为重启前不改地址，配置写错时仍可在旧地址重新下发，**不会一次性失联**——这正是把改址拆成"写配置 + 重启"两步的目的。

### 8.2 显示一张图片（单帧完成）

```
上位机                                                           屏
  │  0x05 SEQ=0x10 {槽位=1, 颜色=01, 864B 点阵}  ─────────────▶ │ 校验长度
  │                                                              │ 写后台缓冲
  │  ◀────────────────  0x50 SEQ=0x10 {00}                       │ 切屏 + 落盘
```

超时未收到 `0x50`：整帧原样重发（SEQ 不变），屏按 (通道, SEQ, 命令字) 判重后**原样重发上次的 `0x50`，不重复执行**；不存在拼接残留。

## 11. 附录 B：CRC 校验程序（Python，用于自测与联调）

```python
def crc16(data: bytes) -> int:
    """CRC-16/X-25：poly 0x1021(ref 0x8408), init 0xFFFF, xorout 0xFFFF"""
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8408 if crc & 1 else crc >> 1
    return (~crc) & 0xFFFF


def swap_nibbles(cmd: int) -> int:
    """请求 <-> 应答命令字互换，如 0x03 <-> 0x30"""
    return ((cmd & 0x0F) << 4) | ((cmd & 0xF0) >> 4)


def build(cmd: int, seq: int, data: bytes = b"") -> bytes:
    body = seq.to_bytes(2, "big") + bytes([cmd]) + len(data).to_bytes(2, "big") + data
    return b"\x55\xAA" + body + crc16(body).to_bytes(2, "little")


def parse(buf: bytes):
    """从字节流解析一帧，返回 (cmd, seq, data, 已消费字节数)；未成帧返回 None"""
    i = buf.find(b"\x55\xAA")
    if i < 0 or len(buf) - i < 9:
        return None
    seq = int.from_bytes(buf[i + 2:i + 4], "big")
    cmd = buf[i + 4]
    ln = int.from_bytes(buf[i + 5:i + 7], "big")
    if ln > 8192 or len(buf) - i < 9 + ln:
        return None
    body = buf[i + 2:i + 7 + ln]
    crc = int.from_bytes(buf[i + 7 + ln:i + 9 + ln], "little")
    if crc16(body) != crc:
        return None
    return cmd, seq, buf[i + 7:i + 7 + ln], i + 9 + ln


def pack_bitmap(width: int, height: int, pixels) -> bytes:
    """pixels[y][x] -> 1bpp 行优先，bit0 为最左像素"""
    stride = (width + 7) // 8
    out = bytearray(stride * height)
    for y in range(height):
        for x in range(width):
            if pixels[y][x]:
                out[y * stride + (x >> 3)] |= 1 << (x & 7)
    return bytes(out)


if __name__ == "__main__":
    assert crc16(b"123456789") == 0x906E
    assert swap_nibbles(0x09) == 0x90
    # A.7 全屏填充红色
    print(build(0x04, 2, b"\x01").hex(" ").upper())
    # A.10 8×8 示例图片（DATA = 槽位 + 颜色 + 点阵，无显示方式字节）
    print(build(0x05, 0x10, b"\x00\x01" + bytes([0xAA] * 8)).hex(" ").upper())
    # A.3 重启
```
